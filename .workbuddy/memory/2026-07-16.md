## 安全要点整改（devops-automation，05:42）
- 原计划隐患：`git add -A`+`git commit` 会把快照提交到当前分支（如 main）污染主分支历史；且 `git add -A` 可能把 `.env`/密钥等敏感文件提交推走。
- 整改 1（备份不污染主分支）：改用底层 plumbing `git add → write-tree → commit-tree → branch -f` 把 `backup/auto` 指向当前工作树，绝不改动当前分支、不触发预提交钩子（也无"绕过钩子"争议）。隔离验证：master 仍仅 1 提交，backup/auto 累积历史。
- 整改 2（敏感文件防泄露）：staged 阶段按 `.env`/密钥/`token`/私钥等模式自动 `git reset` 排除并告警；验证 `.env` 不在快照内。
- 整改 3（部署目标围栏）：batch-deploy 拒绝写入项目根、`.git`、`node_modules`、个人目录、系统目录；项目内子目录仅告警不阻断。验证个人目录与项目根均被拦截（exit 1），合法子目录正常。
