## 测试发现并修复的 2 个真实 Bug

### Bug 1：StockSearch 下拉不渲染（getMarketLabel 空指针）
- `src/components/organisms/input/StockSearch.tsx` 的 `getMarketLabel(industry)` 对 `undefined` 调用 `.toUpperCase()` 抛错
- 真实数据流中 `industry` 来自 `inputService.searchStocks` 返回的 `m.market`（SH/SZ/HK），但测试 mock 用 `market` 字段 → `industry` 为 undefined → 渲染崩溃
- 修复：`getMarketLabel(industry: string | undefined)` 增加空值守卫，返回「—」占位标签

### Bug 2：inputHubStore.searchStocks 阻塞/抛错
- 初版改为 `async` 后在方法体内裸调用 `refreshExistingSymbols()`（兄弟 store 方法，不在作用域）→ `ReferenceError: refreshExistingSymbols is not defined`，整个搜索 reject，下拉永远不展开
- 根因关联：store 的 searchStocks 原会 `await listStocks()`（真实 dataBridge.query），在 jsdom 中挂起 → 搜索无响应
- 修复：移除方法内对 `refreshExistingSymbols` 的裸调用；existingSymbols 由组件 mount 时 `refreshExistingSymbols()` 刷新（fire-and-forget，不打断搜索）

## Dialog X 关闭按钮失灵（2026-07-19 用户报告）

**症状**：七维配置页「接口测试」弹窗点 X 关不掉（实测所有用 `Dialog` + `DialogContent` 默认 X 的弹窗都关不掉，包括 ApiTestDialog 等）。

**根因**：`src/components/molecules/Dialog.tsx` 中 `DialogClose` 仅是个空 `<button>`，没绑关闭行为。X 按钮由 `DialogContent` 内部用 `DialogClose` 包裹（line 61-66），点击既不调 `dialog.close()` 也不触发 `close` 事件 → 父 Dialog 的 `useEffect` 监听不到 → `onOpenChange(false)` 不触发 → 弹窗关不掉。

**为什么测试没拦住**：
- `Dialog.test.tsx:148` 那个 "DialogClose 渲染关闭按钮，点击触发 onClick" 测试**只断言 onClick 透传**（`expect(handleClose).toHaveBeenCalledTimes(1)`），完全没验证点击后弹窗真的关闭。
- "open=false 时调用 dialog.close()" 测试只验证 `open` prop 变化触发关闭（受控路径），不验证 X 按钮（非受控路径）。
- "dialog 原生 close 事件触发 onOpenChange(false)" 测试手工派发 `close` 事件，同样绕开 X 按钮的真实链路。
- **教训**：测试断言「onClick 透传」≠ 测试断言「关闭行为」——典型的「测试通过但 bug 仍存在」案例。

**修复**：
- `Dialog.tsx` `DialogClose` 加 onClick handler：`closest('dialog').close()`，依赖原生 close 事件回弹到父 Dialog 的 `useEffect` → `onOpenChange(false)`，与现有架构一致无侵入。同时补 `type="button"` 防御性兜底。
- `Dialog.test.tsx` 加回归测试「DialogContent 默认 X 关闭按钮点击后真正关闭 dialog（回归：2026-07-19 bug）」，断言 `HTMLDialogElement.prototype.close` 被调用 + `onOpenChange(false)` 被触发。
- 顺手把 `beforeEach` 中 `HTMLDialogElement.prototype.close` mock 改成「派发 close 事件」，更贴近浏览器原生行为，原有 13 个测试不破。
