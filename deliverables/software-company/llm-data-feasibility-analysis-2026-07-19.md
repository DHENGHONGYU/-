## 一、现状痛点

### 1.1 FinSightV9 数据维度覆盖现状（共 8 维）

| 数据维度 | 当前数据源 | 状态 | 问题描述 |
|----------|-----------|------|----------|
| 行情（日线） | Tushare 5000 积分 | ✅ 可用 | 日线数据正常获取 |
| 财务数据 | Tushare 5000 积分 | ✅ 可用 | 基础财务指标可获取 |
| 市值/估值 | Tushare 5000 积分 | ✅ 可用 | 市值、PE、PB 等可用 |
| 股东户数 | Tushare 5000 积分 | ✅ 可用 | 股东户数变化可获取 |
| 行业分类 | Tushare 5000 积分 | ✅ 可用 | 行业归属数据正常 |
| **公告** | 东财直连爬虫 | ⚠️ 部分可用 | 公告维度可用但需维护爬虫，Tushare 公告接口需单独权限 |
| **新闻** | 东财爬虫 → CSV 降级 | ❌ 不可用 | 爬虫反爬失效；Tushare 新闻接口（major_news）需单独开权限，当前积分无权（40203） |
| **研报** | 东财爬虫 → CSV 降级 | ❌ 不可用 | 爬虫参数无效；Tushare 研报接口（report_rc）需 8000 积分，当前仅 5000 积分无权限 |

> **结论**：8 维数据中 2 维完全缺失（新闻、研报），1 维脆弱可用（公告），整体数据完整率仅 62.5%。

### 1.2 爬虫维护成本

| 成本类别 | 具体情况 | 量化估算 |
|----------|----------|----------|
| 端点变化 | 东财网站约 3-6 个月调整一次 HTML 结构或 API 参数，每次需 2-4 小时排查修复 | ~24 工时/年 |
| 反爬升级 | Cookie 校验、频率限制、验证码等机制持续升级；曾被运营商判定异常流量风险 | 不可量化，存在封 IP 风险 |
| 数据质量 | 爬虫获取的数据需要额外清洗（字段映射、去重、格式标准化） | ~12 工时/年 |
| 精神成本 | 免费数据源退潮趋势明显（2025 年 yfinance 停摆事件为前车之鉴），不确定性高 | 持续的焦虑和不确定感 |

### 1.3 Tushare 积分权限限制

```
当前积分：5000（充值 500 元）
├── 可访问：日线行情、财务数据、股东户数、行业分类、基础信息
├── 不可访问：
│   ├── 新闻（major_news）：需单独开权限（与积分无关）
│   ├── 研报（report_rc）：需 8000 积分正式权限（当前仅 2000 积分试用）
│   ├── 公告（announcements）：需单独开权限
│   └── 分钟级行情：需单独付费约 1000 元/月
└── 升级路径：20000 积分套餐 ≈ 2000 元/年（仍不能保证覆盖所有单独权限接口）
```

### 2.2 各方案详述

#### 方案 A：纯 Tushare（20000 积分套餐）

- **成本**：充值 2000 元 ≈ 20000 积分
- **覆盖**：可解锁研报接口（8000积分）及大部分特色数据接口
- **不确定性**：新闻（major_news）、公告（announcements）接口属于"单独开权限"类别，与积分无直接关系——即使充值到 20000 积分也可能需要额外申请
- **风险**：2025 年 8 月 Tushare Pro 曾因非技术因素停运近一周（机房代理商纠纷），单一依赖存在"鸡蛋放在一个篮子里"的风险

#### 方案 B：Tushare + 爬虫（当前方案）

- **成本**：500 元/年（Tushare 5000 积分）
- **当前状态**：新闻和研报两个维度已降级到 CSV，实际数据完整率仅 5/8 = 62.5%
- **根本问题**：爬虫的维护成本（约 36 工时/年）被隐性化，且反爬升级是不可逆趋势

#### 方案 C：Tushare + LLM 搜索（⭐ 混合方案，推荐）

- **成本**：Tushare 500 元/年 + LLM API 约 50-100 元/年
- **原理**：结构化数值数据（行情、财务、股东户数）走 Tushare，非结构化文本（公告摘要、新闻要点、研报评级）走 LLM 联网搜索
- **优势**：兼顾数据精度和成本，两全其美

#### 方案 D：纯 LLM

- **成本**：LLM API 约 50-300 元/年（模型选择和调用频率差异）
- **原理**：所有数据维度都通过 LLM 联网搜索获取
- **核心缺陷**：精确数值（如股东户数 32,456 户、市盈率 15.73）LLM 容易出错或引用过时数据，不适合量化回测

#### 方案 E：开源聚合工具

- **成本**：0 元（但学习成本约 20-40 工时，且全部为 Python 生态）
- **代表库**：AKShare（800+ API，最活跃）、Baostock（历史数据全、无实时）、efinance（轻量，A/HK/US）
- **FinSightV9 兼容性问题**：项目为 TypeScript/Node.js 技术栈，需通过子进程桥接 Python 或使用 Node.js 等价物
  - npm `stock-api`：零依赖，支持 A/HK/US 实时行情，自动兜底（tencent→sina→eastmoney）
  - npm `big-a-api`：基于腾讯证券，支持 K 线和实时价格
  - npm `ashare-sdk-ts`：Python Ashare 的 TS 移植版
  - 这些 JS/TS 库**只覆盖行情数据，不提供新闻/研报/公告**

#### 方案 F：商业终端低价版

| 产品 | 年费 | 个人可用性 | 适合 FinSightV9？ |
|------|------|-----------|-------------------|
| Wind 金融终端 | 20,000-30,000 元 | 需机构账号 | ❌ 远超预算 |
| Choice 金融终端 | 个人版 2000-4000 元 | ✅ 个人可买 | ⚠️ 昂贵，功能过剩 |
| Choice（东财证券达标） | 0 元（日均资产≥30万） | ✅ | ⚠️ 有资产门槛 |
| JoinQuant 聚宽 | 基础版免费 / VIP 999元/年 | ✅ | ⚠️ 主要是量化回测平台 |
| 理杏仁 | 518 元/年 | ✅ | ⚠️ 侧重基本面分析，无 API |
| 同花顺 iFinD | 机构级（万元级） | 需机构 | ❌ 远超预算 |

## 三、LLM 方案深度分析

### 3.1 模型选择对比

| 模型 | API 输入价格 | API 输出价格 | 联网搜索 | 中文金融理解 | 推荐指数 |
|------|-------------|-------------|----------|-------------|----------|
| **DeepSeek V3.2** | ¥2.0/百万 token（缓存未命中）<br>¥0.2/百万 token（缓存命中） | ¥3.0/百万 token | ✅（通过腾讯云知识引擎/第三方） | ⭐⭐⭐⭐⭐ 国产最强 | ★★★★★ |
| **Qwen-Plus** | ¥0.8/百万 token | ¥2.0/百万 token | ✅（阿里云百炼原生支持） | ⭐⭐⭐⭐⭐ 中文优秀 | ★★★★★ |

| **文心一言 4.5 Turbo** | ¥0.8/百万 token | ¥0.32/百万 token | ✅（百度原生） | ⭐⭐⭐⭐ | ★★★ |

> **推荐组合**：日常使用 **DeepSeek V3.2**（性价比最优，2026 年 2 月发布，Agent 能力增强）+ 备用 **Qwen-Plus**（联网搜索生态更成熟）

### 3.2 成本估算（方案 C 混合方案）

#### 基础假设

| 参数 | 取值 |
|------|------|
| 自选股数量 | 30 只 |
| LLM 覆盖维度 | 3 个（公告、新闻、研报） |
| 更新频率 | 月均 1 次（公告/研报不是每天都有新内容） |
| 每次查询总 token | ~25,000（输入 20,000 + 输出 5,000） |
| 缓存命中率 | 40%（同一只股票同一个月内多次查询可缓存） |

#### 成本计算

```
月度查询量 = 30 只 × 3 维度 × 1 次 = 90 次
月度 token 消耗（无缓存）= 90 × 25,000 = 2,250,000 tokens
月度 token 消耗（40% 缓存命中）= 输入 1,350,000 × (0.6×2.0 + 0.4×0.2) + 输出 450,000 × 3.0
                                = 输入 1,350,000 × 1.28/百万 + 输出 450,000 × 3.0/百万
                                = 1.728 + 1.35
                                = 3.078 元/月
```

| 模型 | 月度成本（30只×3维×月更） | 年度成本 |
|------|--------------------------|----------|
| DeepSeek V3.2（官方 API） | ~3-5 元 | **~36-60 元** |
| Qwen-Plus（阿里云百炼） | ~2-4 元 | **~24-48 元** |
| Qwen-Turbo | ~1-2 元 | **~12-24 元** |
| GPT-4o-mini + Web Search | ~$2-4（~14-29 元） | **~170-350 元** |

#### 方案 C 总成本

```
Tushare 5000 积分       500 元/年
DeepSeek V3.2 API        60 元/年（取上限）
网络/杂费                 0 元（已有）
─────────────────────────────────
合计                    560 元/年
```

> 仅比当前方案 B（500 元/年）多出约 **60 元/年**，但多了新闻和研报两个完整维度。

### 3.3 数据质量评估

#### LLM 搜索 vs Tushare 结构化数据

| 评估维度 | Tushare 结构化 | LLM 联网搜索 | 差距 |
|----------|---------------|-------------|------|
| 公告标题+摘要 | ⭐⭐⭐⭐⭐ 结构化字段 | ⭐⭐⭐⭐ 可提取，但可能存在遗漏 | 可接受 |
| 公告全文 | ⭐⭐⭐ 接口不返回全文 | ⭐⭐⭐⭐ 可搜索到原文链接 | LLM 略优 |
| 新闻要点 | ⭐⭐⭐⭐ 来源固定（新华网等） | ⭐⭐⭐⭐ 来源可指定 | 相当 |
| 新闻时效 | ⭐⭐⭐⭐ 日级 | ⭐⭐⭐⭐⭐ 实时（几分钟前） | LLM 更优 |
| 研报评级+目标价 | ⭐⭐⭐⭐⭐ 结构化数值 | ⭐⭐⭐ 可提取但不保证完整 | Tushare 显著更优 |
| 研报全文 | ⭐ 不可用 | ⭐⭐⭐ 可找到部分免费研报 | LLM 可用 |

#### FinSearchComp 基准测试结论（字节 Seed & 哥大商学院，2025）

> - 配备搜索的模型比无搜索模型在金融任务上提升 **40.8/29.0/8.1 个百分点**
> - 无搜索模型在时效性任务上得分为 **0**
> - DeepSeek R1 + 金融插件比裸模型提升 **31.9 个百分点**
> - 但即使最强 AI，金融搜索任务也只能"及格"（非满分）

**结论**：LLM 搜索在公告标题/新闻要点场景完全可用；在研报评级/目标价提取上需要加校验逻辑。

### 3.4 潜在风险

| 风险类别 | 具体风险 | 严重程度 | 缓解措施 |
|----------|----------|----------|----------|
| **幻觉** | LLM 可能虚构公告内容或研报评级数字 | 🔴 高 | 强制要求输出附带来源 URL；关键数字交叉验证 |
| **引用断链** | 搜索到的网页可能被删除或改版 | 🟡 中 | 自建缓存 + 快照机制 |
| **时效性偏差** | LLM 可能混淆"本月"和"上月"的时间范围 | 🟡 中 | Prompt 中使用绝对日期（YYYY-MM-DD）而非相对时间 |
| **来源质量** | 搜索结果可能包含论坛、自媒体等低质量来源 | 🟡 中 | 限制搜索域（如限定 eastmoney.com.cn、cninfo.com.cn 等） |
| **合规风险** | 个人研究工具引用 LLM 生成内容的合规性 | 🟢 低 | 在 UI 显著位置标注"数据仅供参考，不构成投资建议" |
| **API 涨价** | LLM API 价格可能上涨（DeepSeek 2025 年 2 月曾涨价 2-4 倍） | 🟡 中 | 多模型备份（Qwen-Turbo 作为降级方案） |

### 4.2 数据流架构

```
定时任务 (cron: 每月1日 & 每周一)
│
├── 结构化数据采集（Tushare API）
│   ├── 行情日线 → SQLite 表 stock_daily
│   ├── 财务数据 → SQLite 表 stock_financial
│   ├── 股东户数 → SQLite 表 stock_holders
│   └── 行业分类 → SQLite 表 stock_industry
│
└── 非结构化数据采集（LLM 搜索 Agent）
    ├── 公告搜索
    │   ├── 检查 SQLite 缓存（同一公告 hash 去重）
    │   ├── 搜索："{股票名} {股票代码} 最新公告 site:cninfo.com.cn"
    │   ├── LLM 提取：标题、日期、公告类型、核心摘要、原文链接
    │   └── 存储到 SQLite 表 announcements
    │
    ├── 新闻搜索
    │   ├── 搜索："{股票名} 最新消息 2026年7月 site:eastmoney.com"
    │   ├── LLM 提取：标题、来源、日期、要点（3-5条）
    │   └── 存储到 SQLite 表 news
    │
    └── 研报搜索
        ├── 搜索："{股票名} 券商研报 评级 目标价 2026"
        ├── LLM 提取：机构、评级、目标价、核心观点
        └── 存储到 SQLite 表 research_reports
```

### 4.3 缓存策略

| 缓存项 | 缓存周期 | 刷新触发 | 说明 |
|--------|----------|----------|------|
| 公告 | 永久缓存，按 hash 去重 | 新公告出现时追加 | 历史公告不会变，只需追加新公告 |
| 新闻 | 7 天 | 每周刷新 | 新闻时效性强，但旧闻仍有参考价值 |
| 研报 | 30 天或手动刷新 | 每月刷新 | 研报更新频率低（券商约每季度覆盖一次） |
| LLM 搜索结果 | 24 小时 | 下次请求时 | 避免同一问题重复搜索消耗 API 费用 |

### 4.4 成本总览

| 成本项 | 年度预算 |
|--------|----------|
| Tushare Pro 5000 积分 | 500 元 |
| DeepSeek V3.2 API（主力） | ~60 元 |
| Qwen-Turbo API（备用/降级） | ~10 元 |
| 服务器/带宽 | 0 元（本地运行） |
| **合计** | **~570 元/年** |

> 对比当前方案 B（500 元/年 + 约 36 小时隐性维护工时），方案 C 多花 ~70 元/年但消除 2 个数据盲区，性价比极高。

## 五、实施建议

### 5.1 推荐方案

**方案 C：Tushare + LLM 混合方案**，理由：

1. **成本不变质**：仅比当前方案多 ~70 元/年（14% 增幅），换来新闻+研报两个维度从 0 到 1
2. **技术可行**：主理人已验证 LLM 可搜索到茅台公告和工业富联研报（10 秒出结果）
3. **风险可控**：精确数值仍走 Tushare（不受 LLM 幻觉影响），非结构化文本走 LLM（自然容错）
4. **可持续**：不依赖爬虫维护，不需要高额商业终端费用

### 5.2 分阶段落地路径

| 阶段 | 优先级 | 内容 | 预估工时 | 产出 |
|------|--------|------|----------|------|
| **P0** | 🔴 必须 | LLM 搜索 Agent 核心逻辑：公告搜索+提取+缓存 | 3-5 天 | 公告维度从 ❌→✅ |
| **P0** | 🔴 必须 | LLM 搜索 Agent：新闻搜索+提取+缓存 | 2-3 天 | 新闻维度从 ❌→✅ |
| **P1** | 🟡 应该 | LLM 搜索 Agent：研报搜索+评级提取 | 2-3 天 | 研报维度从 ❌→✅ |
| **P1** | 🟡 应该 | 前端 UI：在股票详情页展示公告/新闻/研报卡片 | 3-5 天 | 用户可以查看非结构化数据 |
| **P1** | 🟡 应该 | 数据交叉验证层：LLM 搜索到的数值 vs Tushare 结构化数据比对 | 1-2 天 | 降低幻觉风险 |
| **P2** | 🟢 可选 | 多模型降级策略：DeepSeek 不可用时自动切换 Qwen-Turbo | 1 天 | 提高可用性 |
| **P2** | 🟢 可选 | 搜索计时+Token 用量监控面板 | 1-2 天 | 成本可视化 |
| **P2** | 🟢 可选 | 爬虫方案退役：移除东财爬虫代码，CI/CD 中去掉相关依赖 | 1 天 | 减少维护负担 |

**总预估工时**：14-22 天（单人开发）

### 5.3 风险缓解措施

| 风险 | 缓解措施 | 触发条件 |
|------|----------|----------|
| LLM 幻觉导致错误信息展示 | ① 每条信息附带来源 URL ② 关键数字（评级、目标价）加"仅供参考"标注 ③ P1 阶段做交叉验证 | 上线即实施 |
| DeepSeek API 不可用 | ① 自动降级到 Qwen-Turbo（成本相近）② 本地缓存保证历史数据可用 | API 调用失败 3 次 |
| Tushare 再次停运 | ① 方案 D（纯 LLM）作为极端备份 ② AKShare 免费接口作为行情备份 | Tushare 中断 >24 小时 |
| LLM API 涨价 | ① 多模型不锁定单一供应商 ② 核心数据走 Tushare 不受 LLM 价格影响 | 月度费用超预算 50% |
| 搜索结果被反爬限制 | ① 使用正规搜索引擎 API（非爬虫）② 多搜索源备份（百度+搜狗+Bing） | 搜索返回空结果 |
