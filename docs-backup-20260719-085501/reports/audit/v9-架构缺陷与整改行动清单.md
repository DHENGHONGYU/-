## 一、缺陷分层诊断

### 1.1 按严重程度分层

| 层级 | 缺陷类型 | 数量 | 说明 |
|:---|:---|:---|:---|
| L0 阻断性 | 架构原则违背 | 0 | 当前无 P0 级阻断缺陷；五层架构、ACL、DataBridge 合规 |
| L1 功能性 | 功能未实现/未持久化 | 4 | 策略回测占位、收藏/筛选/分页曾未持久化（已修复）、Store 未接入组件 |
| L2 结构性 | 状态分散 / Store 与组件脱节 | 19 | 大量组件仍使用 useState，无独立 Zustand Store |
| L3 集成性 | 路由/链接/导航残留 | 3 | 临时原型路径、Hub 导航路径不明确、可扩展模块标注待建 |
| L4 文档性 | 文档与代码漂移 | 0 | 批次0 DOC-001~007 已收敛 |

### 1.2 按架构层级分层（五层模型）

```
L5 展示层（pages / components / apps）
   └─ 问题：组件内大量 useState，状态无法跨组件共享
   └─ 整改：将状态下沉/上提到独立 Zustand Store

L4 应用层（apps/）
   └─ 问题：App 入口直接管理局部状态，未使用 Store
   └─ 整改：App 组件仅做路由/布局分发，状态由 Store 持有

L3 引擎/服务层（services / core）
   └─ 问题：部分服务返回结果未通过 DataBridge 转发，事件不可追溯
   └─ 整改：写操作/关键事件统一走 DataBridge.forward + 审计日志

L2 数据层（data / store）
   └─ 问题：Store 已存在但组件未接入（commandStore / outputStore）
   └─ 整改：补齐缺失 Store，修正已有 Store 的接入方式

L1 基础设施层（lib / config）
   └─ 问题：暂无
   └─ 整改：保持
```
