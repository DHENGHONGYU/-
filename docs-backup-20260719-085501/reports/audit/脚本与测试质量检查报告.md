## 六、总结与建议

### 整体评价

- **审计脚本一致性：中等偏上**。dead-code 和 layer-calls 脚本质量较高，hardcode 脚本存在检测范围遗漏，doc-sync 脚本精度不足。
- **测试覆盖度：中等偏低**（约 32%）。Store 和 MCP 层覆盖较好，cockpit/、apps/、config/ 层几乎空白。
- **脚本测试完整性：低**。所有 audit 脚本均无单元测试。

### 优先修复建议

**P0（立即修复）：**
- 无

**P1（高优先级）：**
1. 扩展 audit-hardcode.ts 颜色检测范围，增加 src/cockpit/ 和 src/apps/
2. 补充 audit-layer-calls.ts 的 store 层依赖方向检测
3. 为 cockpit/ 核心模块（widgetEngine、widgetRegistry）补充测试
4. 为 engineStore、executionStore、tradingStore 等核心 Store 补充测试

**P2（中优先级）：**
1. 补充 types/ 层和 agents/ 层的分层检测规则
2. 优化 audit-doc-sync.ts 的匹配算法，降低误判率
3. 为 apps/ 层（App 分发器）补充基础测试
4. 为 config/ 层关键配置文件补充单元测试
5. 为核心 audit 脚本（layer-calls、hardcode、dead-code）编写单元测试

**P3（低优先级）：**
1. 补充 constants/ 层的测试
2. 补充 portal/ 层的测试
3. 为其余 audit 脚本补充测试
