## 一、各模块功能定位与数据流向（要点①）

### 1.1 模块划分与层级归属（对齐 AGENTS.md 分层）

| 模块ID | 模块名 | 层级归属 | 功能定位 |
|---|---|---|---|
| **M1** | 设计令牌层 | `constants/` + `config/` | 单一色彩/间距/圆角/动效真相源；所有 UI 经令牌取色，禁用裸 HEX/色类 |
| **M2** | 主题控制层 | `store/` + `core/` | 主题状态(亮/暗/系统)持久化 + 跨 Tab 广播 + 首屏无 FOUC |
| **M3** | 驾驶舱壳层 | `components/cockpit/` | CockpitShell + WidgetShell + 全局签名锚点 SignalSpectrum，统一视觉收口 |
| **M4** | 状态组件层 | `components/ui/states/` | loading/empty/error/skeleton 四态，所有数据 widget 默认接入 |
| **M5** | 数据服务层 | `services/` + `core/`(DataBridge) | 业务数据获取与融合，经 DataBridge.forward() 落库，向 store 注入 |
| **M6** | 输出成品层 | `components/output/` | 复盘结论封装为可预览/可分享/可导出的成品卡 + 叙事流 |
| **M7** | 移动适配层 | `pages/` + `components/` | 核心舱室响应式兜底（栅格降列、触控≥44px） |
| **M8** | 质量闸门层 | `scripts/` + CI | token-scan + lint 禁裸色类 + 截图 diff，规模扩张不丢一致性 |

## 二、模块间联动测试方案（要点②）

> 目标：验证跨模块交互逻辑正确性。每个联动测试绑定一个追溯 ID（见第五章），且遵循 AGENTS.md 事件清理规范（EventBus.subscribe 必配对 unsubscribe）。

### 2.1 联动测试矩阵

| 测试ID | 联动场景 | 触发模块 | 观测模块 | 验证逻辑正确性 |
|---|---|---|---|---|
| **LT-01** | 主题切换联动 | M2 themeStore | M3 全部 widget + M4 四态 + M6 成品 | 切换 dark 后，所有 widget 经 `.dark` 类重渲染；无裸色泄漏；图表暗色变体生效 |
| **LT-02** | 跨 Tab 主题广播 | M2 withBroadcast | 另一 Tab 的 M3 | 任一 Tab 改主题，其余 Tab 经 withBroadcast 同步，无双态漂移 |
| **LT-03** | 锚点数据源联动 | M3 SignalSpectrum | 各 widget 顶栏锚点条 | SignalSpectrum 数据更新 → 所有 widget 锚点条同步（单一数据源，非各自计算） |
| **LT-04** | 四态联动 | M5/store loading|error | M4 states | store 置 loading→显示 Skeleton；error→显示 Error 且可重试；empty→显示 Empty |
| **LT-05** | 成品卡数据联动 | M5 分析结果 | M6 ResultCard | 分析完成 → 成品卡可预览/导出；向导式复盘逐步填充，老手可跳过 |
| **LT-06** | 移动断点联动 | 视口收缩(375px) | M7 布局 | 栅格降列、触控目标≥44px；驾驶舱/复盘卡不崩 |
| **LT-07** | 令牌一致性回归 | M1 令牌变更 | M3/M4/M8 | token-scan 扫描：裸 Tailwind 色类 0 命中（白名单 STOCK 例外除外） |

### 2.2 测试方法与时序

```
单元测试 (vitest)        集成测试 (组件渲染)        端到端 (Playwright 本地)
─────────────────       ───────────────────        ──────────────────────
LT-04 store→states       LT-01 主题→widget 重渲染   LT-02 跨 Tab 同步
LT-07 lint 规则          LT-03 锚点单一数据源       LT-05 成品卡导出
                         LT-06 断点响应             LT-06 移动真机/模拟
```

- **EventBus 清理规范**（AGENTS.md 模板 1）：每个 LT 的 `useEffect` 订阅必须在 cleanup 中 `EventBus.unsubscribe`；测试用 `vi.useFakeTimers()` 须在 `afterEach` 中 `vi.useRealTimers()`。
- **Playwright 限制**：本沙箱内整链路 e2e/截图 diff 受限，LT-02/LT-05/LT-06 标为**本地手动闸门**，不阻塞发布（呼应实操方案 P4 说明）。

## 三、界面布局合理性与操作流程顺畅性（要点③）

### 3.1 布局合理性校验（以 10 条经典原则为尺）

| 原则 | 布局校验点 | 达标判定 | 关联模块 |
|---|---|---|---|
| ①视觉层次 | 每页 3 秒内可指认最重要数字/动作 | 关键数字与次要标签视觉权重拉开 | M3/M1 |
| ②留白节奏 | 卡片/段间距有呼吸感 | 间距令牌化，密集表格分组留白 | M1 |
| ③色彩节制 | 全站仅 1 类关键行动用强调色 | 单一克制强调色公约落地 | M1/M8 |
| ④排版秩序 | 金额/百分比等宽对齐 | tabular-nums 令牌化 | M1 |
| ⑨签名母题 | 一句话说清 V9 视觉招牌 | SignalSpectrum 锚点全局可见 | M3 |
| ⑩有意义的美 | 动效/配色均帮理解非炫技 | 动效来自令牌，无魔法时长 | M1/M3 |

### 3.2 操作流程顺畅性校验（五舱流程）

```
输入舱 ──▶ 分析舱 ──▶ 交易舱 ──▶ 输出舱 ──▶ 指挥舱
  │           │           │           │           │
  └─ 渐进披露：新手向导逐步引导，老手一键跳过 (原则⑦)
  └─ 结果收口：输出舱 复盘叙事流 + 成品卡 (创新1/5)
  └─ 状态可见：每舱 loading/empty/error 四态 (原则⑤)
```

- **顺畅性验收**：从输入到成品卡导出 ≤ N 步（向导式）；任一步可中断重试不丢上下文。
- **安心校验**（原则⑧）：AI 生成内容清晰标注"仅供参考/非建议"，可解释配色浮层说明数据来源（创新 4）。

## 六、可行性结论

| 维度 | 评估 |
|---|---|
| **技术可行性** | 高 — 令牌体系/WidgetShell/SignalSpectrum 已具备，多数阶段为配置+接入，非推倒重来 |
| **风险可控性** | 中 — P3/P4/P5 涉及较多 widget 改造，建议先覆盖核心 8 widget 再推广；Playwright 受沙箱限制已标注本地闸门 |
| **依赖清晰度** | 高 — M1→M8 数据流向与层级归属已在第一章界定，符合 AGENTS.md 分层 |
| **可验证性** | 高 — 16 项 RM 全部绑定量化验收 + 自动闸门 + 联动测试，可追溯 |
| **建议启动点** | **P0(RM-001~003) + P1(RM-004~006)**，低风险高杠杆，W1 内可见效 |
