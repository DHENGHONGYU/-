## 二、步骤 1：文件清点与交叉比对

### 2.1 方法

```
git log --diff-filter=D --name-only -- docs/**/*.md   # 被删除文件
git log -M --diff-filter=R --name-status -- docs/**/*.md  # 被重命名(移动)文件
```

对每个被删除文件，用 basename 在当前 docs 全目录搜索同名新文件；对同名多副本做 MD5 内容哈希区分"真重复（内容相同）"与"同名异体（内容不同）"。

| docs 当前 MD 文件总数 | 875 |
| git 历史中被删除（D）的 MD 文件（去重） | **183** |

| 其中"真缺失"（无任何同名新文件） | **0** ✅ |

| └ 内容完全相同（真重复，可安全去重） | **51** |

### 4.1 恢复判定

## 五、步骤 4：编码规则与命名系统重梳

### 5.1 现状诊断（6 种命名模式混用）

| 模式 | 示例 | 问题 |
|------|------|------|
| 编号前缀 `NN-` | `01-vision-and-goals.md`、`09-quality-gates.md` | 编号在 explanation/ 和 reference/ 各有一套，语义重叠 |
| 日期前缀 `YYYY-MM-DD-` | `2026-06-20-pure-frontend-architecture.md` | ADR/决策日志专用，但与编号体系混排 |
| ADR 编号 `adr-NNN-` | `adr-001-pure-frontend-architecture.md` | 与日期前缀重叠（同一决策两种命名） |
| 中文书名号 `《》` | `《V9核心数据字典与类型定义（整合版）》.md` | 与英文命名混用，跨平台/脚本兼容性差 |
| 全大写 `UPPER_CASE` | `API_CONTRACT.md`、`STATE_MANAGEMENT.md`、`HOOKS_GUIDE.md` | 与 kebab-case 混用，大小写敏感系统易出错 |
| kebab-case | `a11y-checklist.md`、`action-list.md` | 主流但未统一 |

### 5.2 其他结构问题

| 问题 | 现状 | 影响 |
|------|------|------|
| 重复目录 | `07-archive/` 与 `archive/` 内容完全重复 | 单一事实源破坏 |
| 多 changelogs | `reference/changelogs/`、`reports/changelogs/`、`06-project-management/changelogs/` 三处 | 变更日志分散 |
| 空壳目录 | `02-design/` 仅剩 `.md`（迁移标记）+ `blueprints/README.md` | 映射表仍依赖，但实际已废 |
| frontmatter 不一致 | 部分有 `code_version`，部分用 blockquote `Version` | `doc:version-check` 校验覆盖不全 |
| 两套分类体系并存 | 物理层 00-07（explanation/README）+ A-H 八类逻辑（reference/README）| 导航混乱，且都引用失效旧路径 |

### 5.3 重梳方案

#### 原则

1. **统一 Diátaxis 为唯一物理结构**，废弃编号旧目录（`01-requirements/`、`02-design/`、`03-development/`、`05-deployment/` 已空或仅剩标记）。
2. **A-H 八类降级为逻辑标签**（frontmatter `category: A`），不再驱动物理目录。
3. **命名统一为 `kebab-case`**，废弃中文书名号与全大写。
4. **单一事实源**：每个文档只允许存在一处；过程产物归 `reports/`，规范归 `explanation/` 或 `reference/`。
5. **路径同步契约**：移动文档后，必须同步更新 3 处——映射表 §二、代码 `TRIGGER_RULES.docsToUpdate`、各目录 README 索引。

#### 命名规则（提议）

| 文档类型 | 命名规则 | 示例 |
|----------|----------|------|
| 规范/标准 | `kebab-case.md` | `state-management.md`、`api-contract.md` |
| ADR 决策 | `adr-NNN-short-slug.md`（保留编号，去掉日期前缀） | `adr-001-pure-frontend.md` |
| 数据定义 | `kebab-case.data-definition.md` | `cockpit.data-definition.md` |
| 过程报告 | `YYYY-MM-DD-slug.md`（仅 reports/ 下） | `2026-07-14-doc-audit.md` |
| 目录 README | 固定 `README.md` | 各目录自有 |
| 迁移标记 | 删除 `.md` 空壳，改用 `_redirect-map.json` 集中管理 | — |

#### 目录职责（收敛后）

| 目录 | 职责 | 唯一性 |
|------|------|--------|
| `00-meta/` | 治理核心（映射表、看板、注册索引、治理宪法） | 权威 |
| `tutorials/` | 入门教程（当前仅 1 文件，需补齐） | — |
| `how-to/` | 实操指南（开发流程、组件使用、Hook 规范） | — |
| `reference/` | 参考规格（API 契约、数据字典、配置清单、舱室 spec） | 权威 |
| `explanation/` | 概念解释（愿景、架构标准、ADR、设计决策） | 权威 |
| `reports/` | 过程产物（审计、复盘、changelog、草稿） | 归档性 |
| `archive/` | 历史归档（合并 `07-archive/`，删除重复） | 只读 |
| `prompts/` | AI 提示词模板 | — |
| `assets/` | 静态资源 | — |

### 6.1 交叉引用兼容性

| 代码 `TRIGGER_RULES.docsToUpdate` | 当前已全失效，修正后恢复 | ✅ 修正即修复 |
| `_redirect-map.json`（92546 字节） | 已存在集中重定向映射 | ✅ 可承接旧路径兼容 |

### 6.2 脚本测试适配性

| 脚本 | 现状 | 整改影响 |
|------|------|----------|
| `doc:trigger`（doc-update-trigger.ts） | TRIGGER_RULES 路径失效 | 修正 docsToUpdate 后即恢复 |
| `doc:version-check` | 校验 frontmatter `code_version` | 需统一 frontmatter，否则覆盖不全 |
| `doc:crossRefSync`（audit:docs） | 当前退出 0（未覆盖映射表路径校验） | 建议增加 TRIGGER_RULES 路径存在性校验 |
| `doc:gate`（doc-gatekeeper.ts） | **空桩**（exit 0，无实际逻辑） | 建议落地目录结构合规 + frontmatter 完整性检查 |
| `audit:layers` / `lint:colors` | 与文档无关 | ✅ 不受影响 |

### 6.3 自更新逻辑一致性

| 触发链 | 一致性 | 整改要求 |
|--------|--------|----------|
| 代码变更 → TRIGGER_RULES 匹配 → docsToUpdate 写文档 | **断裂**（路径失效） | 修正 docsToUpdate 指向新路径 |
| 写后 → `audit:docs` 引用同步 | 工具存在 | 确保覆盖新路径 |
| T10 版本发布 → `doc:version-check` | frontmatter 覆盖不全 | 统一 frontmatter |

### 6.4 整改风险与回滚

- **风险**：批量移动/重命名可能触发 `audit:atomic`、`audit:layers` 等门禁误报（旧路径引用残留）。
- **缓解**：分批进行，每批后跑 `tsc:prod` + `audit:docs` + `doc:crossRefSync` 验证；`_redirect-map.json` 维护旧→新映射兜底。
- **回滚**：所有操作基于 git，`git revert` 可整体回退。
