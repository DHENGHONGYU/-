## 2.2 用户故事

### US-001：录入候选股票

> 作为投资者，我想手动录入一只股票到意向候选池，以便后续研究。

**验收标准**：
- 输入 symbol 和 name 后保存到 IndexedDB
- 重复 symbol 提示已存在
- 保存后自动出现在意向候选池列表

### US-002：V6 评分

> 作为投资者，我想对候选股票进行九维评分，以便快速筛选优质标的。

**验收标准**：
- 选择股票后触发评分
- 显示综合评分和九维因子得分
- 评分结果持久化到 IndexedDB
- 无网络时使用自动评分（不依赖 LLM）

### US-003：池间流转

> 作为投资者，我想将研究完成的股票从研究精选池推送到观察池，以便跟踪。

**验收标准**：
- ? 支持 candidate → screened → deepDive → watching → archived 流转
- ? 流转通过 DataBridge 信封化
- ? UI 实时反映状态变化
- ? 输入舱提供看板式股票池，每张卡片展示可流转操作

### US-004：模拟交易

> 作为投资者，我想基于评分信号执行模拟买入，以便验证策略有效性。

**验收标准**：
- 根据信号生成买入/卖出建议
- 模拟盘下单并更新持仓
- 计算盈亏和仓位
- 订单持久化到 IndexedDB

### US-005：交易复盘

> 作为投资者，我想记录每笔交易的复盘笔记，以便积累认知。

**验收标准**：
- 关联订单和股票
- 支持文本笔记
- 可搜索、可导出

### US-006：搜索并录入股票

> 作为投资者，我想通过代码/名称搜索股票并一键录入候选池，以便减少记忆成本与输入错误。

**验收标准**：
- 搜索框支持代码、拼音首字母、中文名称模糊匹配。
- 下拉结果展示代码、名称、行业、PE、PB、市值。
- 点击结果可将股票录入意向候选池，重复股票提示已存在。
- 搜索数据源可配置（本地股票库 / AKShare / 候选池过滤）。

### US-007：批量导入预览

> 作为投资者，我想在批量导入前看到每行的有效/重复/无效状态，以便提前修正错误。

**验收标准**：
- 粘贴文本后即时解析，每行显示状态标签。
- 有效行可导入；重复行提示已存在；无效行给出原因（格式错误、交易所缺失、无法识别）。
- 导入过程中展示进度列表与成功/失败统计。
- 支持清空预览区。

### US-008：热门板块推荐

> 作为投资者，我想查看热门板块及其因子得分，以便识别景气赛道。

**验收标准**：
- 展示板块列表与排名。
- 每个板块展示五/七因子进度条或得分。
- 选中板块展示关联股票，支持单条/全部加入候选池。
- 板块轮动建议基于评分差生成（初版可手工维护，后续接入 V4 行业评分）。

### US-009：数据采集测试

> 作为投资者，我想在采集前验证数据源健康与接口可用性，以便确保评分基于最新数据。

**验收标准**：
- 展示多个数据源的健康状态与延迟。
- 支持单只股票基础/K线接口探测。
- 批量采集展示进度与任务状态。
- 清洗检查标识缺失/异常字段。

## 2.3 核心流程

### 流程 1：选股 → 评分

```
用户录入 symbol
  → DataBridge.forward(INSERT_STOCK)
  → IndexedDB stocks 表
  → AnalysisScheduler.analyze(symbol)
  → 读取 stocks / quotes 数据
  → V6 评分计算
  → DataBridge.forward(SAVE_V6_SCORES)
  → IndexedDB v6_scores 表
  → eventBus.emit("scores:changed")
  → UI 更新评分展示
```

### 流程 2：评分 → 信号 → 模拟交易

```
TradingOrchestrator.evaluate()
  → 读取 v6_scores / sector_scores
  → 生成交易信号
  → DataBridge.forward(INSERT_SIGNAL)
  → riskEngine 风控检查
  → DataBridge.forward(INSERT_ORDER)
  → IndexedDB orders 表
  → eventBus.emit("orders:changed")
  → UI 更新持仓
```

### 流程 3：池间流转

```
用户在 PoolView 点击"推送"
  → poolTransitionEngine.validateTransition()
  → DataBridge.forward(UPDATE_STOCK)
  → 更新 stocks.researchStatus
  → eventBus.emit("stocks:changed")
  → 目标池 UI 更新
```

## 2.4 P1/P2 功能规格

### 2.4.1 行业分析 / 板块轮动

**用户故事**：作为投资者，我想查看行业评分与板块轮动信号，以便识别景气赛道。

**验收标准**：
- 展示 V4 七维行业评分（政策契合度、稀缺性、国产替代空间、技术先进性、行业景气度、估值吸引力、情绪热度）。
- 支持按时间维度对比行业评分变化。
- 板块轮动信号基于行业评分差与资金流向生成（Phase 2 初版可手工维护）。
- 评分结果持久化到 `industry_scores` store。

### 2.4.2 策略回测

**用户故事**：作为投资者，我想基于历史评分数据回测买入/卖出策略，以便验证策略有效性。

**验收标准**：
- 支持选择评分阈值、持有周期、标的池。
- 输出胜率、收益率、最大回撤、年化收益。
- 回测结果可导出为 Markdown/CSV。
- 回测引擎不依赖真实交易数据，使用本地历史评分即可运行。

### 2.4.3 交易复盘笔记

**用户故事**：作为投资者，我想记录每笔交易的复盘笔记，以便积累认知。

**验收标准**：
- 笔记可关联订单 `id` 与股票 `symbol`。
- 支持 Markdown 格式。
- 可按 symbol/日期/标签搜索。
- 笔记持久化到 IndexedDB（v1.0.0 新增 store 或通过现有 store 扩展）。

### 2.4.4 研究报告导出

**用户故事**：作为投资者，我想导出个股研究报告，以便存档或分享。

**验收标准**：
- 报告包含股票基本信息、V6 九维评分、智能评分摘要、行业评分、关键 rationale/evidence。
- 支持 Markdown 与 PDF 两种格式。
- PDF 导出使用浏览器打印或轻量库，避免引入大型依赖。

### 2.4.5 AKShare 数据采集

**用户故事**：作为投资者，我想从 AKShare 拉取股票基础数据，以便评分基于真实财务/行情数据。

**验收标准**：
- 可配置 AKShare 服务地址（本地 Docker 或远程代理）。
- 支持拉取单只或多只股票的基础数据（价格、PE、PB、ROE 等）。
- 拉取失败时保留本地数据并提示错误。
- 数据来源字段标记为 `akshare`，并记录 `dataVersion`。

### 2.4.6 择时信号

**用户故事**：作为投资者，我想收到基于估值、技术和事件的买入/卖出信号，以便决定入场和离场时机。

**验收标准**：
- 系统每日收盘后扫描关注标的，生成买入/卖出/持仓/观望信号。
- 信号包含类型、置信度、触发条件快照（PE/PB 分位、RSI、MACD、量比等）。
- 多信号共振时生成综合信号并提升置信度。
- 数据 > 48 小时标记 stale，信号置信度降权或禁止生成。

### 2.4.7 仓位建议

**用户故事**：作为投资者，我想获得单票和组合的仓位建议，以便科学分配资金。

**验收标准**：
- 基于 Kelly 公式计算目标仓位，默认 1/4 Kelly。
- 支持正金字塔/倒金字塔加仓策略参数化配置。
- 组合集中度（赫芬达尔指数）> 20% 或平均浮亏 > 10% 时给出风险预警。
- 仓位建议写入订单的 `planPositionPct` 字段。

### 2.4.8 交易错误识别

**用户故事**：作为投资者，我想让系统自动识别我的交易错误，以便针对性改进。

**验收标准**：
- 支持 12 类错误检测（追涨杀跌、提前止盈、扛单不止损、逆势加仓、贪鱼尾、违反计划、重仓豪赌、报复性交易、FOMO 入场、忽视止损、犹豫错过、过度交易）。
- 每笔交易可被打上 0-N 个错误标签。
- 自动生成纪律评分（0–100）。
- 根据主导错误生成心理画像（追涨型、恐盈型、扛单型、情绪化型、激进型、冲动型）。

### 2.4.9 AI 复盘报告

**用户故事**：作为投资者，我想查看每笔交易和每个周期的复盘报告，以便总结经验。

**验收标准**：
- 六维报告：交易摘要、错误分析、纪律分析、技能发展、行动计划、AI 深度洞察。
- 计算胜率、盈亏比、计划遵守率、止损执行率、仓位管理评分、情绪控制评分。
- 入场/出场质量评分与择时等级（A/B/C/D）。
- 复盘笔记可一键关联到知识库永久笔记。
- **复盘频率**：每日交易复盘（对当日已平仓交易逐笔分析）+ 每周整体复盘（周五 17:00 自动触发，汇总本周全部交易、评分变化、策略执行情况，输出核心结论与操作建议）。
- **复盘输出三要素**：核心结论（盈亏归因 + 数据规律 + 个性化建议）、操作建议（立即/短期1月/长期3月三档行动计划）、操作失误识别（12 类错误标签 + 心理画像 + 纪律扣分）。

### 2.4.10 核心稀缺主题组合

**用户故事**：作为投资者，我想基于评分构建"第四次工业革命稀缺核心资源"主题持仓组合，以便长期配置稀缺龙头。

**验收标准**：
- 交易舱提供"核心稀缺主题组合"面板，展示目标持仓、当前持仓、再平衡计划。
- 组合构建基于 `themeRegistry` 中的主题定义，从 `watching` 池筛选匹配标的。
- 综合评分（V6 + 智能 + 行业）≥ 4.0 的标的方可入选。
- 主题内等权分配，单只标的权重受 `singleMaxPct` / `singleMinPct` 约束。
- 根据当前订单流水计算实际持仓，生成买入/卖出/持有再平衡建议。
- 支持一键刷新组合，重新计算目标持仓与再平衡计划。

**三类股票操作策略差异**：

| 策略分类 | 评分阈值 | 操作策略 | 核心诉求 |
|:---|:---|:---|:---|
| 核心稀缺（core-scarce） | 综合分 ≥ 4.0 | **长期持有**，不轻易卖出，定期再平衡 | 把握第四次工业革命稀缺赛道龙头，享受长期成长红利 |
| 热门动量（hot-momentum） | 3.2 ≤ 综合分 < 3.5 | **高进高出**，紧跟板块轮动，严格执行止盈止损 | 捕捉热门赛道短期动量收益，纪律执行高于一切 |
| 价值洼地（value-bargain） | 3.5 ≤ 综合分 < 4.0 | **监控观察**，设核心观察值，满足触发条件后启动建仓 | 等待估值修复催化剂，避免过早抄底，择机介入 |
| 观察仓（watchlist） | 综合分 < 2.8 | 持续跟踪，不参与交易 | 评分不足，需更多数据验证 |

### 2.4.11 新闻资讯浏览与筛选

**用户故事**：作为投资者，我想浏览财经新闻并根据情感、股票关联、行业进行筛选，以便快速了解市场动态。

**验收标准**：
- 新闻列表支持按来源、分类、情感（正面/负面/中性）、关联股票、关键词筛选。
- 每篇新闻展示情感标签和置信度，支持展开查看全文。
- 新闻自动关联相关股票，点击股票代码可跳转至分析页。
- 情感分析基于规则引擎（中文财经词典），结果缓存至 IndexedDB。
- 新闻去重基于内容哈希（DJB2 算法），避免重复存储。

### 2.4.12 交易持仓管理与策略执行

**用户故事**：作为投资者，我想查看和管理持仓列表，执行补仓/平仓操作，并基于策略引擎自动构建投资组合。

**验收标准**：
- 持仓列表支持按策略类型、交易方向、关键词筛选，支持分页。
- 补仓/平仓操作需经过风控检查（冷却期、仓位上限、行情新鲜度）。
- 持仓数据支持导出为 CSV 文件（含 BOM 的 UTF-8 编码）。
- 策略引擎支持 20 进 13 规则筛选（核心稀缺/价值洼地/热点动量）。
- 组合构建器按主题等权分配，受 singleMaxPct/singleMinPct 约束。
- 仓位计算基于 Kelly 公式（半凯利），整手取整。

### 2.4.13 AI 智能体中心监控

**用户故事**：作为系统管理员，我想监控 AI 智能体的运行状态、系统健康度和诊断报告，以便及时发现和处理异常。

**验收标准**：
- Agent 列表展示各智能体的类型、标签、调用次数、状态和最后活跃时间。
- 支持按类型和状态筛选 Agent 列表。
- 健康监控面板展示各模块的健康评分、状态和附加指标（成功率、响应时间）。
- 诊断报告展示各模块的综合等级、成功率、稳定性评分和诊断详情。
- 所有状态和颜色从 constants 引用，禁止硬编码。

### 2.4.14 数据采集层管理

**用户故事**：作为开发者，我想通过统一的数据采集层管理各 Widget 的数据源，支持 Mock/REST/WebSocket 三种采集方式，并通过环境变量切换。

**验收标准**：
- 支持 MockCollector（模拟数据）、RestCollector（REST API）、WebSocketCollector（实时推送）三种采集器。
- TaskScheduler 管理采集任务的注册、启动、停止、错误恢复。
- MarketDataAdapter 将不同来源的原始数据统一映射为 MarketData 接口。
- 通过环境变量 VITE_DATA_SOURCE_TYPE 控制数据源类型。
- 默认轮询间隔 5 秒，支持 3 次重试 / 10 秒超时。

### 2.4.15 股票筛选双来源与筛选池规模

**用户故事**：作为投资者，我想通过"热门板块核心标的"和"自定义检索"两个来源构建意向筛选池，并将规模控制在 10-15 支，以便聚焦高质量标的。

**验收标准**：
- **来源一：热门板块核心标的**。系统根据最新板块评分推荐核心标的，用户一键将热门板块的龙头标的纳入意向筛选池。
- **来源二：自定义检索**。用户通过代码/名称/拼音搜索股票，手动将自选标的纳入意向筛选池。
- 两个来源的标的统一进入意向筛选池（`intentionPoolStore`），按纳入时间倒序排列。
- **筛选池规模约束**：意向筛选池推荐规模 10-15 支，超出 15 支时提示用户清理低分标的；策略引擎执行 20 进 13 筛选规则（`selectedMaxCount: 13`）。
- 筛选池中的标的自动触发数据采集（基础数据 + 行情 + 财务），采集结果分类存入本地 IndexedDB。
- 采集完成后自动触发行业评分 + 个股评分，评分结果驱动后续分级处理。

### 2.4.16 评分三阈值分级体系

**用户故事**：作为投资者，我希望系统根据评分自动将标的分为三个梯队并匹配对应操作策略，以便实现"长期持有/高进高出/监控观察"的差异化投资管理。

**验收标准**：
- **三阈值定义**（综合评分 = V6 评分 × 0.6 + LLM 评分 × 0.4，双轨校对）：

| 阈值 | 评级 | 策略分类 | 操作策略 |
|:---|:---|:---|:---|
| ≥ 4.0 | strong_buy | core-scarce | 长期持有，定期再平衡 |
| ≥ 3.6 | buy | value-bargain | 监控观察，设核心观察值，择机建仓 |
| ≥ 3.0 | hold | hot-momentum | 高进高出，严格执行止盈止损 |
| < 3.0 | sell / strong_sell | watchlist | 观察跟踪，不参与交易 |

- 评分偏差 ≥ 0.5 时触发人工复核（V6 与 LLM 评分不一致时）。
- 阈值常量统一定义在 `src/config/strategyRules.ts` 和 `src/config/dualStrategyRules.ts`，禁止在其他文件硬编码。
- 分级结果自动写入 `StrategyResult.classification` 字段，驱动策略引擎执行对应操作。

### 2.4.17 真实持仓导入与炒股经验输入

**用户故事**：作为投资者，我想导入券商真实持仓并输入个人炒股经验/教训，以便系统基于真实仓位进行模拟和复盘，同时积累个人认知。

**验收标准**：
- **持仓导入**：支持从券商导出文件（Excel/CSV，兼容同花顺/通达信/东方财富格式）导入真实持仓，写入 `positionPoolStore`。
- 导入时自动解析股票代码、名称、持仓数量、成本价、当前价等字段，字段缺失时用 `NaN` 标记并提示。
- 导入的持仓与模拟盘交易记录关联，支持在模拟盘中对真实持仓执行买卖操作。
- **经验输入**：交易舱/输出舱提供"炒股经验"输入入口，用户可手动输入文字形式的经验/教训。
- 经验输入关联到 `skillDevelopment` 技能发展维度，与自动推导的交易错误检测互为补充。
- 经验记录持久化到 IndexedDB，可按日期/标签搜索，可关联到复盘报告。

### 2.4.18 资金管理与交易纪律框架

**用户故事**：作为投资者，我想将资金按"耐心资本+博收益"双轨配置，匹配不同的交易纪律和 KPI 考核，以便在有限资源下实现长期增值与短期收益的平衡。

**设计哲学**：资金如兵力——资源总是相对有限的（哪怕百万、千万、上亿，相对于市场二十万亿也是有限的），不能平均分散，必须集中优势兵力在核心赛道。

**资金配置（默认 30/70，用户可配置调整）**：

| 资金池 | 默认占比 | 对应策略分类 | 投资周期 | 目标收益 | KPI 考核 |
|:---|:---|:---|:---|:---|:---|
| 耐心资本 | 30% | core-scarce（核心稀缺） | 2-3 年 | 100%-200% | 不考核短期收益，考核持仓定力和选股准确率 |
| 博收益 | 70% | hot-momentum + value-bargain | 短期-中期 | 年化 15% 合格 / 25% 优秀 | 季度收益率 + 月度胜率 + 纪律执行率 |

**博收益 KPI 指标体系**：

| KPI 指标 | 合格线 | 优秀线 | 说明 |
|:---|:---|:---|:---|
| 年化收益率 | ≥ 15% | ≥ 25% | 跑赢沪深 300（约 8-10%） |
| 季度收益率 | ≥ 10% | ≥ 20% | 按季度考核，最核心 KPI |
| 月度胜率 | ≥ 55% | ≥ 65% | 盈利月占比 |
| 单笔止盈 | +10% | — | 触发后可部分止盈或移动止损 |
| 单笔止损 | -5% | — | 严格执行，不扛单 |
| 纪律执行率 | ≥ 80% | ≥ 90% | 计划遵守率 + 止损执行率 |

**大跌应对交易纪律**：

| 场景 | 耐心资本（30%） | 博收益（70%） |
|:---|:---|:---|
| 个股大跌（-5% 以内） | 不操作，继续持有 | 触发止损，执行卖出 |
| 个股大跌（-5% 至 -10%） | 分批加仓（越跌越买） | 已止损离场，观望 |
| 个股大跌（-10% 以上） | 继续加仓，铆住不卖 | 不参与，等待企稳信号 |
| 大盘系统性大跌（-3% 以上） | 加仓核心稀缺标的 | 降仓至 50% 以下，保留现金观望 |
| 大盘暴跌（-5% 以上） | 满仓核心稀缺（如有现金） | 清仓博收益，全面防守 |

**核心原则**：
- **耐心资本"铆住不卖"**：买入核心稀缺标的后锁定，不在意短期波动，2-3 年为周期持有，目标是 100%-200% 收益。这部分是"退休保障"型配置。
- **博收益"纪律至上"**：严格执行止盈止损，不扛单、不追涨、不 FOMO。每次交易必须有技术面+行业面双因子共振信号支撑。
- **大跌是耐心资本的朋友**：核心稀缺标的逢大跌加仓，降低平均成本；博收益标的大跌即止损离场。

### 2.4.19 双因子评估体系

**用户故事**：作为投资者，我希望系统基于"个股技术信号+行业景气度评分"双因子共振来辅助博收益部分的买卖决策，以便提高交易胜率。

**验收标准**：
- **因子一：个股短期技术信号**。系统自动计算 K 线形态、量价关系、MACD/RSI/KDJ 指标、支撑阻力位，输出买入/卖出/观望信号。
- **因子二：行业景气度评分**。基于 V4 七维行业评分（政策契合度、稀缺性、国产替代空间、技术先进性、行业景气度、估值吸引力、情绪热度），输出行业强/中/弱评级。
- **双因子共振规则**：

| 技术信号 | 行业评级 | 操作建议 |
|:---|:---|:---|
| 买入信号 | 强（≥ 3.5） | **买入**（双因子共振，高置信度） |
| 买入信号 | 中（3.0-3.5） | 试探性买入（半仓） |
| 买入信号 | 弱（< 3.0） | 不操作（行业不支撑） |
| 卖出信号 | 弱（< 3.0） | **卖出**（双因子共振，高置信度） |
| 卖出信号 | 中（3.0-3.5） | 减仓（半仓） |
| 卖出信号 | 强（≥ 3.5） | 不操作（行业仍景气，持有） |
| 观望信号 | 任意 | 不操作 |

- 双因子评估结果作为博收益（70%资金）的操作依据，写入交易信号的 `confidence` 和 `reasoning` 字段。
- 耐心资本（30%）不依赖双因子评估，基于评分分级（≥ 4.0）和长期逻辑持有。

## 2.5 异常与边界情况

| 场景 | 预期行为 |
|------|----------|
| 重复录入相同 symbol | 提示「股票已存在」，不覆盖已有数据 |
| 无网络时触发智能评分 | 提示「离线模式，回退到自动评分」 |
| 股票不存在时触发评分 | 返回错误，不生成评分记录 |
| 模拟买入资金不足 | 风控拦截，提示「可用资金不足」 |
| 空股票池 | 显示空状态插画与引导录入按钮 |
| CSV/JSON 导入格式错误 | 提示具体错误行/字段，支持部分导入成功回滚 |
| IndexedDB 初始化失败 | 提示「浏览器不支持本地存储」或「数据库损坏」 |
| LLM 返回非预期格式 | 提示「评分服务异常」，不保存无效结果 |

## 2.6 数据导入/导出格式

### 2.6.1 CSV 导入（意向候选池）

```csv
symbol,name,source
600519.SH,贵州茅台,manual
000001.SZ,平安银行,manual
```

- `symbol` 必填，格式建议 `{code}.{exchange}`。
- `name` 可选。
- `source` 可选，默认 `manual`。

### 2.6.2 JSON 导出/导入（全量数据）

```json
{
  "version": "v9-export-1",
  "exportedAt": 1719192000000,
  "data": {
    "stocks": [...],
    "daily_quotes": [...],
    "v6_scores": [...],
    "intelligent_scores": [...],
    "industry_scores": [...],
    "signals": [...],
    "orders": [...],
    "watchlists": [...],
    "research_logs": [...]
  }
}
```

- 导出包含用户全部本地数据。
- 导入时校验 `version` 字段，不兼容版本提示用户升级。
