## 1. 安全定位与核心原则

### 1.1 产品安全定位

V9 智能投研复盘系统是一款**纯前端本地应用**，采用"**数据不出本地**"的安全架构设计。所有用户数据（股票池、评分记录、交易笔记、研究文档等）均存储在用户本地浏览器的 IndexedDB 和 localStorage 中，**不上传任何服务器**，从根本上消除数据泄露风险。

### 1.2 核心安全原则

| 原则 | 说明 | 实现方式 |
| :--- | :--- | :--- |
| **数据主权** | 用户完全拥有和控制自己的数据 | 纯前端架构 + 本地存储 + 一键导出/删除 |
| **最小化采集** | 只采集必要的最少数据 | 无账号系统、无行为追踪、无遥测上报 |
| **分层加密** | 敏感数据分级加密存储 | AES-GCM 256 + Web Crypto API |
| **透明可控** | 用户清楚知道数据在哪、如何使用 | 数据管理面板 + 导出/删除自助服务 |
| **默认安全** | 安全配置开箱即用 | 默认加密敏感字段 + HTTPS 强制 + CSP |

### 1.3 数据分类分级

| 级别 | 数据类型 | 加密要求 | 存储位置 | 示例 |
| :--- | :--- | :--- | :--- | :--- |
| **L1 公开** | 公开市场数据 | 无需加密 | IndexedDB | 股票代码、行情数据、财务数据 |
| **L2 内部** | 用户操作记录 | 可选加密 | IndexedDB | 股票池、评分历史、筛选条件 |
| **L3 敏感** | 用户个人内容 | 必须加密 | localStorage (加密) | API Key、LLM 配置、个人笔记 |
| **L4 机密** | 认证凭据 | 必须强加密 | localStorage (强加密) | 第三方服务 Token、主密码哈希 |

## 2. 数据存储安全

### 2.1 存储架构概览

```
┌─────────────────────────────────────────────────────┐
│                   浏览器沙箱内                         │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐ │
│  │  IndexedDB  │  │ localStorage│  │  Memory     │ │
│  │  (结构化数据)│  │  (键值对)   │  │  (临时缓存) │ │
│  │  股票池     │  │  LLM API Key│  │  会话状态   │ │
│  │  评分记录   │  │  用户偏好   │  │  计算中间态 │ │
│  │  交易记录   │  │  加密密钥   │  │             │ │
│  │  研究笔记   │  │             │  │             │ │
│  └─────────────┘  └─────────────┘  └─────────────┘ │
│                                                      │
│  数据完全在本地，零服务器上传                          │
└─────────────────────────────────────────────────────┘
```

### 2.2 IndexedDB 存储安全

**存储内容**（L1 + L2 级数据）：
- 股票池数据（基本信息、分组、状态）
- V6 评分记录 / 智能评分记录
- 交易信号 / 订单 / 持仓
- 研究日志 / 知识库文档
- 行业评分 / 板块轮动数据

**安全措施**：
| 措施 | 状态 | 说明 |
| :--- | :--- | :--- |
| 同源策略隔离 | ✅ 已实现 | 浏览器同源策略天然隔离其他网站访问 |
| 结构化解 Schema | ✅ 已实现 | `db-schema.ts` 定义所有 store 结构，版本化迁移 |
| 数据库版本迁移 | ✅ 已实现 | `db-migrations.ts` 支持增量升级，不丢数据 |
| 事务原子性 | ✅ 已实现 | 所有写操作通过 DataBridge 事务保证一致性 |
| 全库加密 | ⚠️ 待实现 | 当前字段级加密，未来可支持全库加密 |
| 数据备份导出 | ✅ 已实现 | 支持 JSON 格式全量导出备份 |

### 2.3 localStorage 加密存储

**存储内容**（L3 + L4 级敏感数据）：
- LLM API Key 与配置
- 用户偏好设置
- 会话状态
- 加密密钥派生材料

**加密实现**：
- **算法**: AES-GCM 256（Web Crypto API 原生实现）
- **密钥派生**: PBKDF2 + SHA-256，迭代 100,000 次（符合 OWASP 2026 推荐）
- **密钥来源**: 设备指纹（命名空间 + browser origin）
- **IV 生成**: 每条记录独立 12 字节随机 IV
- **认证标签**: GCM 模式自带完整性校验，防止篡改

**核心模块**：
- [localStorageCrypto.ts](../../src/lib/localStorageCrypto.ts) — 加密工具函数
- [localStorageManager.ts](../../src/lib/localStorageManager.ts) — 存储管理器

**加密数据结构**：
```typescript
interface EncryptedPayload {
  __encrypted: true      // 加密标记，区分明文旧版
  iv: string             // Base64 编码的 12 字节 IV
  data: string           // Base64 编码的密文
  createdAt: number      // 创建时间戳
  expiresAt: number      // 过期时间戳（0=永不过期）
  version: number        // 数据版本号
}
```

### 2.4 内存数据安全

**措施**：
- 敏感数据（如 API Key）使用后立即从内存中清理
- 所有 Store 状态在用户登出/重置时清空
- 内存缓存有 TTL 过期机制（MemoryCache LRU）
- 防止通过 `window` 对象全局泄露敏感数据

## 3. 数据传输安全

### 3.1 第三方 API 通信

| 数据流向 | 传输协议 | 认证方式 | 数据脱敏 |
| :--- | :--- | :--- | :--- |
| → LLM API (OpenAI/Anthropic等) | HTTPS + TLS 1.2+ | Bearer Token (API Key) | 仅发送评分所需字段 |
| → 行情数据源 | HTTPS | API Key / 无 | 仅请求公开市场数据 |
| → 新闻资讯源 | HTTPS | API Key | 仅请求公开新闻数据 |
| → MCP Server (本地) | 本地进程间 | 本地鉴权 | 不出本地 |

**安全要点**：
1. **API Key 永不明文传输**：请求通过浏览器原生 fetch，Key 仅存在请求头中
2. **HTTPS 强制**：所有外部 API 必须使用 HTTPS，禁止 HTTP 明文
3. **最小数据原则**：只发送第三方服务所需的最少字段
4. **超时控制**：所有外部请求有超时限制（默认 30s），防止挂起
5. **错误处理**：网络错误/超时时优雅降级，不暴露 Key 等敏感信息

### 3.2 无后端架构优势

V9 采用纯前端架构，**没有自己的后端服务器**，因此：
- ❌ 不存在服务端数据泄露风险
- ❌ 不存在数据库拖库风险
- ❌ 不存在中间人攻击（服务端链路）
- ✅ 用户数据从产生到存储全链路在本地
- ✅ 即使第三方 API 被攻破，也无法获取用户的完整数据

## 4. 用户数据权利

### 4.1 数据所有权

> **核心声明**：用户在 V9 中产生的所有数据，所有权完全归用户本人所有。V9 项目方不拥有、不查看、不使用任何用户个人数据。

### 4.2 用户数据权利清单

| 权利 | 说明 | 实现方式 |
| :--- | :--- | :--- |
| **知情权** | 用户知道收集了什么数据、存哪、怎么用 | 本文档 + 设置中的数据管理面板 |
| **访问权** | 用户可以查看自己的所有数据 | 数据导出功能 + 各模块数据浏览 |
| **导出权** | 用户可以导出全部数据 | JSON/CSV/Excel 格式全量导出 |
| **删除权** | 用户可以删除全部或部分数据 | 数据重置功能 + 单项删除操作 |
| **可携带权** | 用户数据格式标准化，可迁移 | 开放 JSON Schema + V6/V9 迁移工具 |
| **更正权** | 用户可以修改自己的数据 | 各模块编辑功能 |

### 4.3 数据导出

**支持格式**：
- **JSON 格式**：全量数据导出，包含所有结构化数据，可用于备份和迁移
- **CSV/Excel 格式**：股票池、评分结果、交易记录等表格数据导出

**导出内容包含**：
- 股票池（所有分组、状态、标签）
- V6 评分历史 + 智能评分历史
- 交易记录 + 订单 + 持仓
- 研究笔记 + 知识库文档
- 行业评分 + 板块轮动数据
- 用户配置 + 筛选条件

### 4.4 数据删除

**删除级别**：
| 级别 | 操作 | 不可恢复 |
| :--- | :--- | :--- |
| 单条删除 | 删除某只股票/某条笔记 | 是 |
| 分类清空 | 清空股票池/清空评分记录 | 是 |
| 全量重置 | 重置所有数据到初始状态 | 是 |

**删除确认机制**：
- 删除操作前二次确认
- 高风险操作（全量重置）需要输入确认文字
- 删除操作不可逆，建议先导出备份

## 6. 第三方服务安全

### 6.1 LLM 服务

**数据安全要点**：
1. **用户可控**：LLM 功能默认关闭，用户需主动配置 API Key 才能启用
2. **透明化**：AI 生成内容有明确标识，用户知道哪些是 AI 输出
3. **最小发送**：只发送评分所需的股票基本信息和因子数据
4. **无持久化**：LLM 对话历史不强制保存，用户可选择是否保留
5. **多模型支持**：支持多家 LLM 服务商，用户自主选择信任的服务商

**API Key 安全**：
- 存储在 localStorage 加密区域（AES-GCM 256）
- 仅在发起请求时使用，不记录到日志
- 不显示完整 Key（掩码显示）
- 用户可随时删除 Key

### 6.2 行情数据源

**数据安全要点**：
1. **仅公开数据**：只请求公开市场行情数据，不上传任何个人数据
2. **本地缓存**：请求结果缓存在本地 IndexedDB，减少重复请求
3. **请求限流**：内置请求频率控制，避免对数据源造成压力
4. **失败降级**：数据源不可用时自动降级到 Mock/缓存数据

### 6.3 MCP Server

**安全模型**：
- MCP Server 在用户本地运行，数据不出本地
- 用户完全控制安装哪些 Server
- ACL 权限矩阵控制每个 Server 的读写权限
- 敏感操作需要用户确认

## 9. 安全事件响应

### 9.1 安全事件分级

| 级别 | 定义 | 响应时间 | 示例 |
| :--- | :--- | :--- | :--- |
| **紧急 (P0)** | 大规模数据泄露/严重漏洞 | 24 小时内 | 加密算法被破解、重大 XSS 漏洞 |
| **高 (P1)** | 局部安全风险/单模块漏洞 | 72 小时内 | 某个 API Key 泄露风险、依赖高危漏洞 |
| **中 (P2)** | 一般安全改进 | 1 周内 | CSP 缺失、安全头不完整 |
| **低 (P3)** | 优化建议 | 排期处理 | 文案优化、交互改进 |

### 9.2 响应流程

```
发现安全问题 → 评估严重级别 → 
  P0/P1: 紧急修复 + 安全公告 + 版本更新
  P2/P3: 排期修复 + 下版本包含
→ 验证修复 → 发布安全更新 → 复盘改进
```
