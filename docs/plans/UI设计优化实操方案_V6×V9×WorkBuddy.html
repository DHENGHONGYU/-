2核心洞察（三方综合）

提炼为可指导落地的判断，而非主观好恶。

1

三方共识：克制单一强调色 + 语义色分层 + 暗色档，是专业工具的标配

V6 用翡翠绿、V9 用青绿、WorkBuddy 用蓝系——都坚守「一个主行动色」。差异只在色相，原则一致。结论：V9 不必换色相，但要更克制（强调色只用于 1 类关键行动），并把暗色档做成一等公民。

2

信息架构同构：WorkBuddy「输入-过程-结果」≈ V9 五舱，但 V9 缺「结果即成品」

V9 已有 5 舱流程骨架，却未像 WorkBuddy 那样把最终产出做成「可预览/可分享的成品卡」。复盘结论散落在页面，缺少"一键成稿"的收口体验。

3

V9 最大短板在「体验层」，不在「设计系统」

令牌、分层、治理已领先；真正缺的是：暗色优先、统一视觉锚点、loading/empty/error 四态、微动效。这些是"用户可感"的部分，恰是 V6 做满、WorkBuddy 做顺的地方。

4

品牌色仍"通用翡翠绿"，需沉淀差异化主色并校验 AA

三方都偏蓝绿，V9 与 V6 主色几乎重合（色相 160）。建议从"通用绿"升级为带辨识度的差异化主色，并对所有前景/背景组合跑 WCAG AA（≥4.5:1）对比度校验。

5

WorkBuddy 的「渐进披露」可解 V9 认知负荷

V9 信息密度高、新手易迷失。借鉴 WorkBuddy 的模式切换（Craft/Plan/Ask）+ 向导式流程，把复盘做成"逐步引导"而非"全屏平铺"。

6

令牌迁移债是落地一致性的头号 blocker

实测 `THEME_TOKENS.color` 仍暴露 `text-blue-500` 等裸 Tailwind 色类；跨 widget 直接写色值会绕过令牌。不先清零，任何"统一视觉"努力都会被新代码稀释。

7

统一锚点 > 统一配色

V6 的「九层漏斗」之所以记忆点强，不是因为配色，而是因为"全局一致的视觉母题"。V9 应植入自己的签名锚点（如"信号强度谱"），让所有 widget 共享同一视觉语言。

8

移动端是 V9 的盲区，却是 V6 的主场

V6 移动优先、单屏凝聚；V9 桌面优先、舱室分散。至少核心舱室（驾驶舱/复盘卡）需做响应式收口，避免"桌面精致、手机崩坏"。

3成熟度再评估（加入体验维度）

在上一轮 V6×V9 工程维度之外，补入 WorkBuddy 启示的「体验范式」维度。

4实操路线图（6 阶段 · 分步落实）

每阶段含「目标 → 具体步骤（贴合 V9 架构）→ 可行性 → 验收闸门」。顺序按依赖与性价比排布。

5分阶段可行性分析

每个阶段从"能不能做 / 依赖 / 风险 / 回滚"四角评估。

P0 基线固化可行性 高 · 纯配置+文档，无运行时风险；依赖无；回滚=删 JSON/ revert AGENTS.md。
P1 暗色优先可行性 高 · 令牌体系已支持 dark；依赖 P0 主色；风险在"暗色令牌覆盖不全"→ 先补 index.css 的 .dark 再上线；回滚=themeStore 切回 system。
P2 视觉锚点可行性 高 · 新增组件+WidgetShell 收口，不破坏既有；依赖 P0；风险低；回滚=移除锚点条。
P3 交互状态可行性 中 · 需改造较多 widget 接入四态；建议先覆盖核心 8 个 widget 再推广；回滚=组件级 revert。
P4 令牌 lint可行性 中 · lint 规则易写，但存量裸色类需批量修；建议分两 PR：先规则(仅 warning)，再清零(升 error)；Playwright 视觉 diff 受本环境沙箱限制，标本地手动闸门。
P5 结果/引导可行性 中 · 涉及输出舱交互重构；依赖 P2 锚点；建议先做"成品卡"MVP 再迭代向导。
P6 移动/巡检可行性 高 · 响应式渐进；巡检 skill 用 SkillManage 沉淀，低风险可持续。
环境约束提醒：本沙箱内 Playwright 整链路 e2e / 截图 diff 受限（需用户授权关闭沙箱或本地手工跑）；curl 抓外网需 dangerouslyDisableSandbox:true。P4 的视觉 QA 先以"令牌扫描"落地，截图 diff 作为本地手动闸门，不阻塞发布。

7优化能力自查清单（12 项）

把本次三方提炼转化为可日常自检的能力项。

  • 主色是否"单一克制"，且全站仅 1 类关键行动使用强调色？
  • 所有前景/背景组合是否通过 WCAG AA（≥4.5:1）？
  • 暗色档是否作为一等公民（非事后补丁）且切换无闪烁？
  • 是否存在全局统一的"视觉锚点/母题"？
  • 所有数据 widget 是否都有 loading/empty/error/skeleton 四态？
  • 是否禁止了裸 Tailwind 色类（令牌迁移债清零）？
  • 动效是否来自令牌（无组件内魔法时长）？
  • 最终产出是否做成"可预览/可分享的成品卡"？
  • 新手流程是否有渐进披露/向导，老手可跳过？
  • 核心舱室是否在移动断点（≤375px）不崩？
  • 是否有自动化视觉 QA（令牌扫描 + 截图 diff）闸门？
  • 是否有常态化设计巡检机制（参考站逆向比对 skill）？
