调研依据与经验来源（点击收起）

本清单综合了公开社区与行业的上线实践经验，并映射到本项目的真实技术栈（React 19 + Vite 6 / Zustand 47 Store + withBroadcast / Tailwind 令牌体系 / Recharts + lightweight-charts / IndexedDB / Mock·REST·WebSocket 三数据源 / LLM 接入 / Playwright + Vitest / 10+ audit 脚本 / 金融监管场景）：

  • 阿里云《上线前检查清单模板》：>60% 线上问题源于上线前准备疏漏；有效清单须“可执行、可更新、可验证”；四阶段（代码构建 / 数据配置 / 部署验证 / 协作沟通），强调灰度 1%→10%→50%→100% 与回滚触发条件、上线后 4h 黄金观察期与复盘。
  • Front-End-Checklist（80k★）：七大维度——HTML / CSS / JavaScript / 性能 / 可访问性 / SEO / 安全；强调将清单集成进 CI/CD（ESLint、Lighthouse budget、axe-core、OWASP ZAP）并随项目演进。
  • 金融 App 合规（腾讯云/安全社区）：网络安全法、等保 2.0（金融通常三级）、PCI-DSS；金融监管总局《加强银行业保险业移动互联网应用程序管理的通知》（4 方面 18 条：备案、网络安全、数据安全、外包）；《个人信息保护法》最小必要、隐私政策与授权、SDK 合规；高频违规集中在超范围收集与未脱敏。
  • 大型 React 应用生产踩坑：首屏白屏、滚动掉帧、输入延迟、“越用越卡”、偶发全局崩溃；根因多为内存泄漏（监听/定时器/订阅未清理）、缺失代码分割与虚拟化、缺少性能预算。

优先级定义：阻断(P0) 不通过禁止上线（事故/数据丢失/合规违法/安全泄露）；高(P1) 强烈建议上线前完成；中(P2) 上线前或首迭代内完成；低(P3) 优化项，可排期迭代。
