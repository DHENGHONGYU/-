一、结论摘要（防"设计全面、实施缩水"）

本次"删除事项"有两类来源，性质完全不同：

  • 源码删除（35 个文件，git --diff-filter=D 已确认从工作树消失）：经逐文件核验，约 30 个属于"架构重构迁移"（pr-6-module-split）——代码从扁平的 services/trading/、pages/*、store/* 重组成领域化的 services/<domain>/、apps/*、data/types/、components/*，功能保留甚至增强（如回测引擎独立成域并补了测试与 MCP 服务；Agent 管理从 1 页扩成 9+ 页套件）。
  • 文档删除（约 212 个，见 docs/文件整理清单.md）：绝大多数是临时产物 / 过程报告 / 旧版副本 / 已废弃文档，不含唯一功能设计；功能设计规格（specs）均保留在 docs/implementation/ 的"保留"清单中。

真正需要"保留并优先修复/完善"的缺口只有约 5 项（见 §三 C 组与 §四），集中在：EngineMonitor 页面被砍（数据层却还在）、ai-center provider 被删导致数据未接线、ArchitecturePage 缺失、pool 类型契约丢失。其余删除均不构成功能缩水。

佐证：对 35 个已删模块做"悬空引用"扫描 → 0 处当前代码仍 import 已删路径；全量 tsc --noEmit 无 error TS（与既有零错误基线一致）。说明删除是干净的重构，未把构建搞断。
