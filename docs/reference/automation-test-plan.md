## 项目目标

1. 覆盖所有五大舱室（输入舱/分析舱/交易舱/输出舱/命令舱）的所有功能点
2. 通过自动化点击操作逐项校对验证功能正确性
3. 详细记录发现的问题，提供对应的解决方案
4. 完成问题汇总分析，出具整改优先级和实施建议评估方案

## 实施流程

### 阶段门禁（必须严格遵守）

1. **每个模块开始前**：检查需求理解清晰，确认测试点
2. **编写测试用例**：基于页面结构和功能，编写 Playwright 测试脚本
3. **执行测试**：运行测试，记录失败
4. **分析问题**：定位失败原因，分析问题根源
5. **修复验证**：修复问题后重新测试，确认通过
6. **更新计划**：标记任务完成，更新进度
7. **进入下一模块**：开始下一个优先级任务

### 质量门禁（每个模块完成后必须通过）

```powershell
npm run build
npx playwright test <module-spec> --project=chromium
# 必须全部测试通过才能进入下一模块
```

## 风险评估与应对

| 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|----------|
| 元素选择器变更 | 中 | 中 | 使用文本定位优先，减少刚性选择器 |
| 页面加载延迟 | 高 | 低 | 添加足够超时，等待元素可见 |
| 数据库数据状态不一致 | 中 | 中 | 每个测试 beforeEach 导航到入口 |
| 异步操作时序问题 | 高 | 中 | 使用 await expect 等待元素可见 |
| CSS 选择器优先级冲突 | 低 | 低 | 使用文本定位替代 |
