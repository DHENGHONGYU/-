
## P0-1 基础通信协议

### 1. StandardEnvelope

系统内所有模块间通信的标准信封格式，采用 `meta + payload` 双层结构，确保消息的可追踪性与统一校验。

| 字段名 | 类型 | 必填 | 描述 | 示例值 |
|--------|------|------|------|--------|
| meta | `EnvelopeMeta` | 是 | 信封元数据，包含来源、目标、动作、追踪ID与时间戳 | — |
| payload | `unknown` | 是 | 消息体，具体类型由 action 决定，可为 null | `{ symbol: "600519.SH", price: 1680 }` |

- **来源定义文件**：`src/core/envelope.ts`
- **存储位置**：不持久化，仅在运行时内存中传递
- **关联实体**：`EnvelopeMeta`、`ModuleId`、`EnvelopeAction`、`EnvelopeTarget`

---

### 2. EnvelopeMeta

信封元数据，描述一条消息的路由信息与追踪属性。所有模块间通信必须携带完整的 meta 信息。

| 字段名 | 类型 | 必填 | 描述 | 示例值 |
|--------|------|------|------|--------|
| source | `ModuleId` | 是 | 消息来源模块标识，共 11 种枚举值 | `"analyzer"` |
| target | `EnvelopeTarget` | 是 | 消息目标地址，共 8 种枚举值 | `"db"` |
| action | `EnvelopeAction` | 是 | 消息动作类型，共 30+ 种枚举值 | `"INSERT_STOCK"` |
| traceId | `string` | 是 | 全链路追踪ID，用于跨模块请求追踪 | `"trace_abc123xyz"` |
| timestamp | `number` | 是 | 消息创建时间戳（毫秒），由 EnvelopeFactory 自动填充 | `1717000000000` |

- **来源定义文件**：`src/config/dbConfig.ts`（接口定义）、`src/core/envelope.ts`（工厂校验）
- **存储位置**：不独立持久化，随 StandardEnvelope 在内存中流转；部分审计场景下写入 `research_logs`
- **关联实体**：`StandardEnvelope`、`ModuleId`、`EnvelopeAction`、`EnvelopeTarget`、`ResearchLog`

---

### 3. ModuleId

来源模块枚举，标识系统内 11 个功能模块。用于消息溯源、权限控制（ACL 矩阵）与日志审计。

| 枚举值 | 模块名称 | 描述 |
|--------|----------|------|
| `fetcher` | 数据采集器 | 负责外部行情、财务等数据的抓取与入库 |
| `stockpool` | 股票池 | 股票池管理、分组、筛选等操作 |
| `analyzer` | 分析引擎 | V6评分、智能评分、行业评分等计算模块 |
| `tradinghub` | 交易中枢 | 交易订单、信号、策略快照的管理中枢 |
| `system` | 系统模块 | 系统级操作，拥有全部读写权限 |
| `user` | 用户操作 | 前端用户直接触发的操作 |
| `rotation` | 轮动模块 | 板块轮动评分与信号检测 |
| `sector` | 板块模块 | 板块定义、板块评分管理 |
| `news` | 资讯模块 | 新闻抓取、情感分析、资讯收藏 |
| `trading` | 交易模块 | 模拟/实盘交易执行 |
| `strategy` | 策略引擎 | 双策略编排、热门板块/价值洼地计算 |

- **来源定义文件**：`src/config/dbConfig.ts`（`MODULE_ID` 常量）
- **存储位置**：不独立存储，作为枚举类型在 EnvelopeMeta、ACL 矩阵等中引用
- **关联实体**：`EnvelopeMeta`、`AclPermission`、`EnvelopeAction`

### 5. EnvelopeTarget

目标枚举，定义消息可投递的目标地址。共 8 种，分为基础设施目标与策略数据流目标两类。

| 枚举值 | 目标类型 | 描述 |
|--------|----------|------|
| `db` | 基础设施 | 数据库层，所有持久化操作的目标 |
| `analyzer` | 基础设施 | 分析引擎，评分计算相关操作的目标 |
| `ui` | 基础设施 | 前端界面，用于状态更新与通知 |
| `tradinghub` | 基础设施 | 交易中枢，交易与信号管理目标 |
| `system` | 基础设施 | 系统级目标，用于全局操作 |
| `strategy:hotSector` | 策略数据流 | 热门板块策略数据流通道 |
| `strategy:valuePit` | 策略数据流 | 价值洼地策略数据流通道 |
| `strategy:rotationSignal` | 策略数据流 | 轮动信号检测数据流通道 |

- **来源定义文件**：`src/config/dbConfig.ts`（`ENVELOPE_TARGET` 常量）
- **存储位置**：不独立存储，作为枚举类型在 EnvelopeMeta 中引用
- **关联实体**：`EnvelopeMeta`、`StandardEnvelope`、`DataChannel`

### 7.1 MatchedTradePair

单笔买入订单与卖出订单按 FIFO 配对后产生的交易对明细，用于计算已实现盈亏、胜率、月度聚合等。

| 字段名 | 类型 | 必填 | 描述 | 示例值 |

| buyDate | `string` | 是 | 买入日期（YYYY-MM-DD） | `"2026-01-15"` |
| sellDate | `string` | 是 | 卖出日期（YYYY-MM-DD） | `"2026-02-20"` |
| quantity | `number` | 是 | 配对数量（股） | `100` |
| realizedAmount | `number` | 是 | 已实现盈亏金额（元） | `1680.5` |

- **来源定义文件**：`src/store/orderStore.ts`
- **存储位置**：运行时派生，不独立持久化
- **关联实体**：`Order`、`TradePair`

### 7.2 TradePair

按 `symbol` 聚合的交易对与持仓信息，由 `buildTradePairs()` 从全部 `Order` 派生而来，是订单域统一总账本的核心中间结构。

| 字段名 | 类型 | 必填 | 描述 | 示例值 |
|--------|------|------|------|--------|
| symbol | `string` | 是 | 股票代码 | `"600519.SH"` |
| buyOrders | `Order[]` | 是 | 买入订单列表 | — |

### 25. DataPacket&lt;T&gt;

数据报文实体，数据流系统中在通道上传输的标准数据包。包含通道标识、数据内容、时间戳与序列号。

| 字段名 | 类型 | 必填 | 描述 | 示例值 |
|--------|------|------|------|--------|

| timestamp | `number` | 是 | 数据生成/发送时间戳 | `1717000000000` |
| seq | `number` | 是 | 序列号，用于顺序校验与去重 | `1024` |

- **来源定义文件**：`src/core/dataflow/dataflowTypes.ts`
- **存储位置**：不持久化，运行时在内存通道中传递
- **关联实体**：`DataChannel`、`ChannelMeta`、`DataCallback`

## 附录 D：数据版本与迁移

### D.1 数据版本号规则

- 采用**语义化版本**（Semantic Versioning）：`主版本.次版本.修订版本`
- 主版本变更：数据结构不兼容变更（字段删除/类型变更）
- 次版本变更：向后兼容的功能新增（新增可选字段）
- 修订版本：Bug 修复、数据修正

### D.2 数据迁移机制

1. **IndexedDB 版本升级**：通过 `dbConfig.ts` 中 `DB_VERSION` 控制
2. **迁移脚本**：`src/data/migrations/` 目录下按版本号命名
3. **自动迁移**：数据库打开时自动检测版本并执行升级
4. **回滚机制**：重要变更前自动备份关键 Store 数据
