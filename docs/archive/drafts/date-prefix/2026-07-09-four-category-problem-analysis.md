# V9系统四类常态问题综合分析报告

**生成日期**: 2026-07-09  
**分析范围**: 配置可见性、运行模拟、数据持久化、页面完整性  
**对比基准**: V6 Pro UI静态组件设计规范

---

## 一、配置可见性问题清单

### 1.1 采集策略配置化不足（P0 - 严重）

**问题描述**: 整体采集策略未做可配置化设计，导致策略调整缺乏灵活性

**具体表现**:
- 采集频率、采集范围、采集优先级、重试策略等核心参数硬编码在 `src/services/fetcher/fetcherClient.ts`、`fetcherAdapter.ts`、`fetcherScheduler.ts` 中
- `src/config/fetcherConfig.ts` 仅定义了基础配置项（数据源列表、维度配置），缺少策略层面的配置
- 页面仅提供简易配置项（开关、简单数值），与原始设计要求的复杂配置能力存在差距

**涉及文件**:
- `src/services/fetcher/fetcherClient.ts` - 重试机制硬编码
- `src/services/fetcher/fetcherAdapter.ts` - 策略和优先级判断硬编码
- `src/services/fetcher/fetcherScheduler.ts` - 调度逻辑依赖硬编码参数
- `src/services/fetcher/fetcherService.ts` - 核心策略在代码中直接定义
- `src/config/fetcherConfig.ts` - 配置项不完整
- `src/pages/input/FetcherConfigPage.tsx` - 页面配置能力不足

**复现步骤**:
1. 进入"数据采集"页面（`/input/fetcher-config`）
2. 观察配置项：仅有数据源开关、采集频率、超时时间
3. 尝试调整采集优先级、重试策略、采集范围 → 无对应配置界面
4. 查看代码发现策略参数硬编码在服务层

**影响范围**: 
- 用户无法根据网络环境、数据源特性灵活调整采集策略
- 策略优化需要修改代码并重新部署
- 与V6版本的灵活配置能力相比明显退化

**严重程度**: P0 - 核心功能缺失，影响系统可用性

**V6对比**: V6版本提供了完整的采集策略配置界面，包括优先级队列、重试策略、采集时间窗口等高级配置项

---

### 1.2 页面配置项简易化（P1 - 高）

**问题描述**: 多个配置页面仅提供简易配置项，与原始设计要求的复杂配置能力存在差距

**具体表现**:

#### 1.2.1 多因子筛选配置（P1）
- **现状**: `MultiFactorFilterPanel` 支持条件组管理，但缺少权重分配、阈值范围设置
- **缺失**: 因子权重动态调整、条件组合优先级、筛选结果预览
- **涉及文件**: 
  - `src/components/analysis/screening/MultiFactorFilterPanel.tsx`
  - `src/store/multiFactorScreeningStore.ts`
  - `src/config/multiFactorScreeningConfig.ts`

#### 1.2.2 七维采集配置（P2）
- **现状**: `SevenDimConfigPage` 提供策略模板、维度开关，但缺少参数精细化调整
- **缺失**: 维度权重自定义、采集深度配置、质量阈值设定
- **涉及文件**:
  - `src/pages/input/SevenDimConfigPage.tsx`
  - `src/store/sevenDimConfigStore.ts`
  - `src/config/collectConfig.ts`

#### 1.2.3 LLM配置（P2）
- **现状**: `LLMConfigWidget` 提供模型选择、API Key配置，但缺少高级参数
- **缺失**: Temperature/Top-P配置、上下文窗口动态调整、成本预估
- **涉及文件**:
  - `src/components/shared/LLMConfigWidget.tsx`
  - `src/config/llmConfig.ts`

**复现步骤**:
1. 进入各配置页面
2. 观察配置项类型：多为开关、下拉选择、简单数值输入
3. 尝试调整高级参数（权重、阈值、优先级）→ 无对应界面
4. 对比V6设计文档发现配置能力不足

**影响范围**: 
- 用户无法精细化调整系统行为
- 系统适应性受限，难以应对多样化场景

**V6对比**: V6版本提供了更丰富的配置项，支持权重分配、阈值范围、优先级设置等高级功能

---

## 五、设计原则违背问题清单

### 5.1 采集策略配置化不足（P0 - 严重）

**问题描述**: 整体采集策略未做可配置化设计，违背"配置可见"原则

**详细分析**: 见 1.1 节

**违背原则**: 
- 配置可见性：策略参数硬编码，用户无法调整
- 灵活性：策略调整需要修改代码
- 可维护性：配置分散在多个文件中

**修复建议**:
1. 在 `src/config/fetcherConfig.ts` 中补充策略配置项
2. 修改 `src/services/fetcher/` 下的服务文件，从配置读取策略参数
3. 在 `src/pages/input/FetcherConfigPage.tsx` 中增加高级配置界面
4. 创建 `src/store/fetcherStrategyStore.ts` 管理策略配置状态

---

### 5.2 页面配置项与设计要求差距（P1 - 高）

**问题描述**: 页面仅有简易配置项，与原始设计要求的复杂配置能力存在差距

**详细分析**: 见 1.2 节

**违背原则**:
- 功能完整性：缺少高级配置项
- 用户控制权：用户无法精细化调整
- 设计一致性：与V6设计规范不符

**修复建议**:
1. 梳理V6版本的配置项清单
2. 对比V9当前配置项，识别缺失项
3. 按优先级补充缺失的配置项
4. 优化配置界面交互设计
