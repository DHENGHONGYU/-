# R03 回滚方案与演练文档 — V9 智能投研复盘系统

> **文档版本**：v1.0 ｜ **日期**：2026-07-08 ｜ **关联清单项**：R03（回滚方案与演练）
> 配套文档：《发布计划与评审-r01.md》（含 R02 构建门禁）

---

## 1. 回滚定位与原则

本系统为**个人级静态前端应用**（Vite SPA，产物 `dist/`），无独立后端服务（交易接口为 dev 中间件 mock，生产不打包）。因此回滚以**静态资源回滚为主、数据兼容为辅**：

1. **静态回滚优先**：保留上一版 `dist/` 备份，出问题即重新部署旧包，最快、最稳。
2. **数据向后兼容**：IndexedDB 写入须保留旧 schema 可读能力，避免新版本写坏旧数据导致无法回滚。
3. **不破坏接口契约**：前端调用的 `/api/v1/trade`（mock）与 LLM 代理须保持兼容或优雅降级，禁止发布破坏性变更。
4. **先决策后执行**：触发条件达成即升级决策，5 分钟内启动 SOP。

## 2. 回滚触发条件（Triggers）

满足**任一**即触发回滚评估：

| 等级 | 触发条件 | 示例 |
|---|---|---|
| 🔴 立即回滚 | P0 门禁在发布后失效 | 上线即白屏、主链路 500 |
| 🔴 立即回滚 | 数据损坏 / 丢失风险 | IndexedDB 写入异常、复盘数据错乱 |
| 🟠 评估回滚 | 核心功能阻断率 > 5% | KAI 评分不可用、导出失败 |
| 🟠 评估回滚 | 性能劣化明显 | 首屏 > 5s、滚动严重掉帧 |
| 🟡 观察修复 | 非阻断缺陷 | 个别文案错误、低频样式问题 |

> 黄金观察期（R01 §7）内任一点命中 🔴 即执行回滚，不等待。

## 3. 回滚类型与措施

### 3.1 静态资源回滚（主手段）
- 保留发布前 `dist.backup.<timestamp>`（R01 §6 步骤⑥已生成）。
- 重新部署该备份目录即可，无需重新构建。

### 3.2 数据兼容回滚
- **IndexedDB 版本化**：数据层须使用 `dbVersion` 常量；新版本升级须提供 `onupgradeneeded` 迁移，且**保留旧数据可读**。
- **withBroadcast 版本号**：跨 Tab 广播消息带 schema 版本，旧 Tab 收到不识别消息时静默忽略而非崩溃。
- **禁止中途破坏性 schema 变更**：如确需改字段，先兼容读写旧结构一版本，下个迭代再清。

### 3.3 接口 / 特性降级
- `/api/v1/trade` 与 LLM 代理：前端须对失败做兜底（mock 数据 / 提示重试），不因接口异常整页崩。
- 若引入特性开关（feature flag），回滚=关开关，不重新部署。

### 3.4 配置回滚
- 主题令牌、数据源开关等走 `src/constants` / `src/config`，变更可逆；保留上一版配置快照。

## 5. 回滚标准操作程序（SOP）

```bash
# ① 确认触发条件并记录时间（T0）
# ② 定位上一版备份
ls -d dist.backup.* | sort | tail -1     # 取最新备份

# ③ 重新部署备份（静态托管场景）
#   方案 A：直接把备份目录作为新 dist 发布
cp -r "dist.backup.<上一版时间戳>" dist_rollback
#   按托管方流程上传 dist_rollback（或切换符号链接 / 重启静态服务）

# ④ 版本标签回退（如通过 git 管理发布）
git tag -a "rollback.$(date +%Y%m%d_%H%M%S)" -m "回滚至 v9.rc.<上一版>"
#   如需代码级回退：git checkout <上一版 tag> 后重新 build

# ⑤ 重启 / 刷新静态服务（依托管方式）
#   CloudStudio / 静态服务器：重新指向备份目录并重启

# ⑥ 验证（见 §6）
```

## 6. 回滚后验证（Post-Rollback Verification）

| 检查点 | 标准 | 命令 / 动作 |
|---|---|---|
| 首页可加载 | 无白屏 | 打开预览地址 |
| 主链路可用 | 选股→KAI→导出 正常 | 手动 + `npm run test:e2e` |
| 数据可读 | IndexedDB 旧数据正常展示 | 打开已有复盘记录 |
| 接口降级 | LLM/交易接口异常时不崩 | 断网测试 |
| 版本一致 | 当前版本 = 回滚目标版 | 检查页脚/构建号 |
