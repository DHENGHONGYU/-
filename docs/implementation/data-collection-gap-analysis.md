## 三、需汇总分析的关键领域

### 3.1 【优先级P0】真实数据源接入

**现状**：Python `collect_endpoints.py` 仅返回Mock数据，8个维度中0个真实接入

**F盘方案**：
- D7 四层架构：L1免费直连(腾讯/新浪/东财) → L2 Python数据库(AKShare/BaoStock) → L3 AI兜底(Kimi Work) → L4 Mock
- D9 33项连通性测试：腾讯财经PASS，新浪/网易/AKShare存在已知问题
- D1 36个白名单站点：证监会/巨潮/东财/财联社/金十数据等

**V9差距**：
1. Python端 `/api/collect/basic` 和 `/api/collect/kline` 标注 `# TODO: 接入AKShare`
2. 缺少6个维度的Python采集接口（03筹码/04公告/05新闻/06行业/07指数/08研报）
3. 缺少四层降级编排逻辑
4. strategyDataAdapter定义了腾讯/东财API类型但无实际fetch调用

**建议汇总分析**：
- 逐维度梳理AKShare可用接口（D7中已有对比表）
- 制定L1→L2→L3→L4降级策略
- 参考D9的33项连通性测试结果选择稳定数据源

### 3.2 【优先级P0】资讯采集引擎

**现状**：newsService仅提供保存接口，无主动采集能力

**F盘方案**：
- D1 智能资讯采集方案：Scrapy-Redis分布式 + 三级去重(URL/SimHash/语义) + 六维质量评分

**V9差距**：
1. 无爬虫/crawler模块（0%）
2. 无URL/SimHash/语义三级去重（0%）
3. 无六维质量评分模型（0%）

| 数据质量/标签 | 100% | 5% | 95% |
| **加权平均** | **100%** | **~12%** | **~88%** |

### 核心判断

1. **架构骨架已建**：V9的Fetcher/DataBridge/采集器抽象/配置层架构设计合理，与F盘方案的四层引擎理念一致
2. **真实接入为零**：所有Python端点为Stub，8个维度中0个真实接入AKShare
3. **资讯能力极弱**：F盘方案的核心价值（36站点采集+三标签+六维质量+16事件Schema）在V9中几乎空白
4. **黑天鹅完全缺失**：F盘已有完整Python实现可直接复用，但V9未启动
5. **AI升级未开始**：V2路线（LangGraph/FinGPT/Exa/Milvus）完全未启动

### 建议优先汇总方向

> **最需要汇总分析的三个领域**：
> 1. **真实数据源接入方案** — 汇总D7四层架构 + D9连通性测试 + AKShare接口清单，制定8维度逐维度接入计划

> 3. **黑天鹅监控集成** — 汇总D6的42信号源 + 已有Python实现，评估集成到V9的可行性与路径
