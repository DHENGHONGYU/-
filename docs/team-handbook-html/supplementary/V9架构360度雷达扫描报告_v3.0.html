5已修复项详情（10项）
P0-1 级联删除 P0 阻塞
databridge.ts — 新增 80 行级联逻辑
在 DataBridge 中实现 14 张 IndexedDB 表的级联删除，彻底解决删除订单后关联数据成为孤儿的问题。涵盖持仓、交易记录、V6 分析、新闻缓存等关联表。
P0-2 路由守卫 P0 阻塞
routeGuard.tsx 新建 + App.tsx 集成
新建 RouteGuard 组件实现路由鉴权拦截，在 App.tsx 中集成。配合 ACL 矩阵实现按钮级权限控制，彻底修复鉴权穿透问题。
P1-1 充血模型 P1 严重
entityValidators.ts 新建
创建 validateOrder、validateStock、validateV6Score 等充血模型验证函数，将业务规则内聚到领域实体，减少散落在各处的校验逻辑。
P1-2 useCase 层 P1 严重
src/services/useCase/ — 3 个用例文件
建立用例层目录，封装核心业务编排逻辑（如订单创建流程、分析执行流程），将跨 Service 的复杂协作收敛到单一入口，提升可维护性。
P1-3 AGENTS.md P1 严重
AGENTS.md — 10 章节规范
编写 AI 行为约束契约文档，涵盖分层规则、四步集成编码契约、类型安全、零硬编码、路由注册、引擎架构、验证命令、数据库版本管理、LLM 透明度等 10 个章节。
P1-4 僵尸组件删除 P1 严重
3 个僵尸组件 — 共 1776 行
识别并删除 3 个超过 400 行且零引用的僵尸大组件，释放代码库维护负担。删除前通过全量搜索确认无引用依赖。
P1-5 Store 拆分 P1 严重
orderStore.ts 851 → 489 行
将臃肿的 orderStore 拆分为 489 行核心逻辑，抽出衍生状态和辅助方法到独立模块。上帝 Store 数量从 4 个降至 3 个。
P1-6 Service 收敛 P1 严重
11 个 async action 收敛
将页面直接调用的 11 个 async action 收敛到 Service 层，页面不再直接调用 Service 方法，通过 Store 中转数据流。
P1-8 事务工具 P1 严重
withOptimisticUpdate.ts 新建
创建乐观锁事务边界工具，封装 "乐观更新 → API 调用 → 回滚/确认" 三步事务模式，解决跨 Store 数据一致性问题。
P1-9 类型逃逸 + 循环依赖 P1 严重
agentTypes.ts 提取共享类型 + 类型逃逸修复
通过提取 agentTypes.ts 消除模块间循环依赖。同时修复所有 as any 和 @ts-expect-error 类型逃逸，生产代码实现零逃逸。

P1-7 静默回退 P1 严重
704 个 ESLint Critical 级问题
catch 块中空处理或仅 console.error 的静默回退，生产环境中可能导致错误被吞掉。建议逐步引入统一的错误处理中间件。
P1-10 魔法数字 P1 严重
527 个 ESLint Major 级问题
代码中存在的硬编码数值（3位以上）和内联样式颜色值。需逐步提取到 config 层和 constants 层，配合样式主题系统统一管理。
P2-1 类型测试覆盖 P2 优化
tests/__tests__/types/ 目录
复杂泛型和关键接口的 Expect<Equals> 类型级测试覆盖不足。建议为核心数据结构（StockData、OrderEntity、V6Score）添加编译时类型守卫。
P2-2 DTO 层完善 P2 优化
Service 层边界接口
部分 Service 接口直接透传 Entity 给 UI，缺少 DTO 转换层。建议在 Service 边界引入 ResponseDTO 模式，隔离领域模型与展示模型。
P2-4 注释代码清理 P2 优化
全局扫描
代码库中存在被注释掉的旧逻辑和调试代码块。建议通过自动化工具扫描并清理，保持代码库整洁。
