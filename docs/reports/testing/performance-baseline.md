### 1.3 体积优化建议

#### P0 级优化（预期收益：首屏 -40% 以上）

1. **transformers.js 按需加载**
   - 当前：主包包含 transformers (824KB)
   - 方案：将本地嵌入/AI 功能改为动态 import
   - 预期收益：首屏 -824KB（约 -200KB gzip）

2. **charts 图表库懒加载**
   - 当前：主包包含完整图表库 (603KB)
   - 方案：图表组件改为 React.lazy + Suspense
   - 预期收益：首屏 -603KB（约 -177KB gzip）

#### P1 级优化（预期收益：首屏 -20%）

3. **excel / pdf 导出功能懒加载**
   - 当前：构建时全量包含 (429KB + 422KB)
   - 方案：导出按钮点击时才动态 import
   - 预期收益：首屏 -850KB（约 -280KB gzip）

4. **html2canvas 懒加载**
   - 当前：主包包含 (202KB)
   - 方案：截图功能按需加载
   - 预期收益：首屏 -202KB（约 -48KB gzip）

#### P2 级优化（预期收益：首屏 -10%）

5. **mechanismHealthStore 体积优化**
   - 当前：172KB，偏大
   - 方案：分析依赖树，移除不必要的依赖
   - 预期收益：~50KB

6. **路由级懒加载深化**
   - 当前：部分大页面已做懒加载
   - 方案：所有非首屏页面全部 lazy import
   - 预期收益：首屏 -100~200KB

## 7. 当前结论

### 7.1 构建性能

- ✅ **构建时间**：10.57s，达标（< 15s）
- ⚠️ **首屏体积**：720KB (217KB gzip)，超预算
- ⚠️ **大 chunk 数量**：多个 > 400KB 的 chunk 需懒加载
- 🔴 **最大优化点**：transformers + charts + excel + pdf 四大块可全部懒加载

### 7.2 预期优化效果

完成 P0 优化后：
- 首屏 JS 体积：720KB → ~200KB（**减少 72%**）
- 首屏 gzip 体积：217KB → ~60KB（**减少 72%**）
- LCP 预期提升：从估算 3-4s → 2s 以内

### 7.3 下一步行动

1. **立即执行**：transformers / charts / excel / pdf 懒加载改造
2. **本周内**：建立 Lighthouse 自动化基线测试
3. **下周**：接入 web-vitals 性能监控
4. **持续**：每次 PR 检查包体积，防止性能退化
