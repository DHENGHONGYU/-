## 二、告警规则说明

| 规则ID | 触发条件 | 级别 | 响应动作 |
|:---|:---|:---|:---|
| ALERT-01 | 关联 `src/` 目录累计修改 > 5 次，但文档未同步 | 🟡 需关注 | 本迭代内安排审阅更新 |
| ALERT-02 | 健康度评分 < 50 | 🔴 过时 | 立即安排修订或废弃 |
| ALERT-03 | 健康度评分 50-79 | 🟡 需关注 | 本迭代内安排审阅更新 |
| ALERT-04 | 文档最后更新 > 90 天 | 🔴 过时 | 立即评审是否仍有效 |
| ALERT-05 | 文档最后更新 31-90 天 | 🟡 需关注 | 安排审阅 |

## 三、定期复查机制

| 复查频率 | 复查范围 | 执行人 |
|:---|:---|:---|
| 每两周（迭代末尾） | 所有 🟡 和 🔴 文档 | Documentation Governor |
| 每次代码合并后 | 变更涉及的关联文档 | 开发者自查 |
| Code Review 时 | 变更是否同步更新文档 | Reviewer |

---

## 四、文档同步 DoD（Definition of Done）

每个开发任务完成后，必须满足以下条件方可标记为完成：

- [ ] 涉及的代码变更已提交
- [ ] 关联的架构文档已同步更新（如有架构变更）
- [ ] 关联的数据字典已同步更新（如有类型/接口变更）
- [ ] 变更日志已追加到对应文档的 `change_log`
- [ ] 文档 `last_updated` 已更新为当前日期
- [ ] 文档版本号已按语义化规则递增
- [ ] `npm run audit:docs` 通过
