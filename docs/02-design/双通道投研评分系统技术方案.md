# 双通道投研评分系统技术方案（可行性论证报告）

> 文档定位：系统性可行性论证 + 可执行技术方案  
> 适用系统：V9 智能投研复盘系统  
> 编制依据：基于 V9 现有真实模块（`fetcherConfig` / `localKnowledgeStore` / `v6-engine` / `LLMScoreEnhancer` 等）的现状基线，非从零设计  
> 合规底线：本系统为**个人股票研究/复盘辅助工具，非金融产品、不涉及即时交易**；所有 AI 生成内容须标注"仅供参考/非投资建议"

---

## 核心结论（摘要）

本方案采用**"双通道数据采集 + 双层评分（因子骨架 A + LLM 受控增强 B）"**架构。经核查，V9 已具备该架构的**全部核心雏形**：通道一（行情主动采集）、通道二（人工文章本地化知识库 `LocalDoc`）、因子解析层（`v6-engine LayerCalculator`）、LLM 增强层（`LLMScoreEnhancer`，已实现"增强不替代、离线透传、失败回退"）。

**可行性结论：高**。主要工程风险不在"能不能做"，而在三处待完善点：① 通道二当前为"存储/检索"层，缺**结构化因子抽取**管道；② LLM 增强层**未强制"依据可追溯"闸**（路线 B 的幻觉/一致性风险未完全约束）；③ 缺**实时检索**能力（当前 LLM 增强仅基于已采集材料，非联网检索）。第六章给出可执行完善方案。

## 第一章 可行性方案梳理

### 1.1 系统定位与目标

| 项 | 内容 |
|---|---|
| 定位 | 个人投研复盘辅助分析工具（非交易系统） |

## 第二章 性能优越性评估

### 2.1 数据采集环节

- **通道一（主动采集）**：基于接口协议轮询/订阅，结构化字段直采，延迟低、吞吐可控；行情数据天然带时间戳，时效性强。
- **通道二（人工本地化）**：文章经人工梳理后入库，**信噪比远高于爬虫资讯**；本地存储（IndexedDB）零网络依赖、隐私自主、离线可用；不与行情抢带宽。

### 2.2 数据处理环节

- **双通道互补降低单点失效**：通道一失效（接口限流/停牌）时，通道二仍可提供基本面/研报维度支撑；反之亦然。
- **本地化去重**：`LocalDoc.hash` / `NewsArticle.hash` 机制避免重复计入；人工库体积小、检索 O(log n) 级。

### 2.3 分析环节

- **A 层（因子解析）**：纯规则计算，毫秒级、确定性、可并行（各 Layer 独立）。
- **B 层（LLM 增强）**：仅在 A 层结果之上做"复核增强"，且 `LLMScoreEnhancer` 对确定性层（L3a/L3v/L-1/L8）**跳过 LLM 调用**，LLM 开销被限制在少数可增强层，整体时延可控。

### 2.4 量化对比（相对单通道/纯 LLM 方案）

| 维度 | 单通道(仅行情) | 纯 LLM 方案 | **本双通道方案** |
|---|---|---|---|
| 数据覆盖面 | 中（仅量价/资讯） | 依赖 LLM 知识，**易过期** | **高（量价+基本面+研报）** |
| 评分可复现性 | 高 | 低（同输入不同分） | **高（A骨架锁定）** |
| 时效敏感性 | 高 | 低（训练知识滞后） | **高（通道一实时）** |
| 隐私/合规 | 中 | 低（常需上云） | **高（本地为主）** |
| 抗幻觉 | 高 | 低 | **高（B层受A约束+可加依据闸）** |

### 第二章结论与建议

✅ 双通道在**覆盖面、可复现性、时效、隐私**四维同时占优，是性能优越性的核心来源。  
💡 建议：在 B 层补充"依据追溯闸"后，可将"抗幻觉"从"中"提升至"高"，形成对纯 LLM 方案的代差优势。

## 第三章 数据采集双通道设计说明

### 3.1 通道一：APP 通过接口协议主动采集

- **协议形态**：基于 `fetcherConfig` / `collectConfig` 定义的采集器，对接行情/资讯接口（如新浪财经等），结构化字段直采。
- **数据类型**：实时/历史行情（`dailyQuotes`）、资讯（`NewsArticle`，含情感分析 `SentimentCache`）。
- **特征**：带时间戳、可增量更新、支持订阅/轮询双模；失败可重试、限流可降级。

### 3.2 通道二：人工自主收集高质量文章 → 本地化结构化资料库

- **入库形态**：`LocalDoc` 结构——`symbol / name / content / category / tags / sourcePath / size / addedAt`。
- **分类体系**：`研报 / 财报 / 行业分析 / 新闻 / 策略笔记 / 其他`，覆盖投研全维度。
- **操作流程**：`LocalKnowledgePage` 支持浏览、关键词搜索、文件夹扫描（`scanFolder`）、示例导入；经 DataBridge（`local_docs` 频道）跨模块同步。
- **特征**：信噪比高、零网络依赖、隐私自主、可离线复盘；人工梳理天然带"标的—维度—观点"结构化标签。

### 3.3 双通道协同与对齐

- **对齐键**：以 `symbol`（标的）为枢纽，通道一的量价信号与通道二的基本面文章在标的维度聚合。
- **去重**：各自 hash 机制；跨通道不重复计分，仅在融合层做证据互补。
- **互补**：通道一解决"现在怎么样"（量价/资讯），通道二解决"为什么/长期逻辑"（研报/策略）。

### 第三章结论与建议

✅ 双通道已具备存储与检索基础，人工库是**差异化数据资产**（竞品难低成本复制）。  
💡 建议：当前通道二仅"存储+全文检索"，**缺结构化因子抽取**（如从研报自动抽取"景气/估值"维度评分线索）。P1 阶段应补"文章→因子线索"抽取管道，使通道二真正进入 A 层计算，而非仅作展示。

## 第四章 核心分析逻辑

### 4.1 关键影响因子提取与解析（路线 A — 骨架）

- **来源**：SKILL-C / SKILL-N 框架提炼的核心知识维度 → 落地为 `v6-engine` 的多层 `LayerCalculator`（L0~L8）。
- **机制**：每层输出 `score / summary / evidence / risks`，确定性层（L3a/L3v/L-1/L8）纯规则、不调 LLM，保证可复现。
- **优势**：评什么、怎么评**先验锁定**，跨样本/跨时间可比，可审计。

### 4.2 大模型检索增强与交叉验证（路线 B — 受控补充）

- **现有实现**：`LLMScoreEnhancer.enhance()` 在 A 层结果之上调用 LLM，对可增强层（L0/L1/L2/L4/L5/L6/L7）做复核增强；离线/失败/未配置时**透传原始结果**（优雅降级）。
- **交叉验证**：LLM 基于已采集材料（通道一资讯 + 通道二文章）做多源汇总，识别 A 层未覆盖的风险（`risks` 合并）。
- **当前局限**：增强仅基于"已采集材料"，**非联网实时检索**；且未强制 LLM 输出"引用了哪段材料"作为依据。

### 4.3 因子骨架 + LLM 补充的融合机制（关键设计）

推荐沿用并强化 `LLMScoreEnhancer` 范式，增加**"依据追溯闸"**：

```
最终分 = A主分(权重~85%) + B补充信号(权重≤15% × 置信度)
约束：B的补充结论必须附带"可追溯引用片段"（来自通道一/二的具体材料）
      → 无依据 → 该部分权重归零，仅留"待人工复核"标记
      → 依据存疑/低置信 → 降权计入
```

此机制使 B 的"灵活"被锚定，既补 A 的覆盖盲区，又不污染主分的可复现性。

### 第四章结论与建议

✅ V9 已是"因子骨架 + LLM 增强"融合的正确范式，**方向无误**。  
💡 建议：将 `LLMScoreEnhancer` 升级为"带依据追溯闸的受控增强"——在 `callLLM` 的 JSON schema 中新增 `citations: [{source, snippet}]` 字段，解析时校验非空，否则按失败回退。这是把"路线 B 更聪明"转化为"路线 B 可信"的关键一跃。

## 第五章 创新性与独创性论证

### 5.1 国内外相似方案 / 竞品对比

| 方案类型 | 代表 | 数据来源 | 评分范式 | 短板 |
|---|---|---|---|---|
| 传统量化 | 券商量化模型 | 行情/财务 | 纯因子(A) | 无研报/人工洞察，覆盖窄 |
| 纯 LLM 投研 | 各类 AI 选股 Bot | LLM 训练知识 | 纯生成(B) | 幻觉、不可复现、时效差 |
| 通用 RAG+LLM | 财经 AI 问答 | 联网检索+LLM | 检索+生成 | 常上云、隐私弱、评分无骨架 |
| **本方案** | **V9 双通道** | **主动采集+人工本地库** | **A骨架+B受控增强** | **待补依据闸/实时检索** |

### 5.2 差异化优势

1. **双通道数据融合**：竞品多为单源（行情或联网），本方案叠加"人工高质量本地库"——信噪比与隐私兼得，且人工库是**无法被爬虫低价复制的壁垒**。
2. **因子骨架优先**：在 LLM 泛滥的投研场景，坚持"确定性评分主干 + 受控生成补充"，保证**可审计、可复现**（合规底线）。
3. **本地优先架构**：IndexedDB + 本地密钥（`llmConfig` 加密存储），数据自管、零强制上云，契合个人研究工具定位。

### 5.3 设计精妙性

- **增强不替代**（`LLMScoreEnhancer` 范式）：LLM 永远在 A 层之上做"增量"，而非"重算"，从架构上杜绝了纯 LLM 的不一致风险。
- **分层可开关**：确定性层跳过 LLM，LLM 开销与风险被精确隔离在少数层。
- **优雅降级链**：离线→透传；失败→回退规则；未配置→原始分——任何单点失效都不破坏主评分。

### 第五章结论与建议

✅ 本方案在"个人投研复盘工具"这一细分场景具备**工程化组合创新**（非单点首创，但组合稀缺）。  
💡 建议：创新性论述聚焦"双通道 + 因子骨架 + 受控增强"三位一体，避免"全球首创"式夸大；对外表述保持"个人研究辅助工具"定位。

## 第六章 可行性评估与完善

### 6.1 落地可行性综合评估

| 维度 | 评分(1-5) | 说明 |
|---|---|---|
| 技术可行性 | 4.5 | 核心模块已落地，补缺即可 |
| 数据可行性 | 4.0 | 双通道已具备，通道二需补因子抽取 |
| 风险可控性 | 4.0 | A骨架兜底，B层风险可约束 |
| 合规可行性 | 5.0 | 个人工具定位，本地优先，免责清晰 |
| **综合** | **4.4** | **高可行性，建议推进** |

### 6.2 潜在风险与不足

| 风险 | 影响 | 缓解 |
|---|---|---|
| B层幻觉/无依据 | 污染评分可信度 | 加"依据追溯闸"（4.3） |
| 通道二质量参差 | 主观偏差进因子 | 入库时结构化校验 + 来源标注 |
| 数据时效性 | 行情过期/知识库旧 | 通道一增量更新；B层接实时检索 |
| LLM成本/密钥 | 调用费用、本地密钥管理 | 仅可增强层调用；`llmConfig` 加密存储 |
| 一致性漂移 | 同输入不同分 | A骨架锁定 + ICC 基准测试 |

### 6.3 完善后的可执行技术方案（里程碑）

**M1（通道二因子化）**
- 新增 `localDocFactorExtractor`：从 `LocalDoc.content` 抽取 SKILL 维度线索（景气/估值/催化剂），写入 `LocalDoc.factorHints`。
- 接口契约：`extract(doc: LocalDoc): FactorHint[]`；失败降级为 `[]`（不阻断）。

**M2（B 层依据闸）**
- 扩展 `LLMScoreEnhancer.callLLM` 的 JSON schema，新增 `citations: [{source, snippet}]`。
- 解析时校验 `citations.length > 0` 且 `snippet` 命中通道一/二材料，否则按失败回退 A 层。
- 新增配置 `enhancer.requireCitations: boolean`（默认 true）。

**M3（实时检索可选扩展）**
- 新增 `webRetrievalAdapter`（可选启用）：在 B 层调用前注入实时检索片段，标注 `source: 'web'`，与本地材料同等参与依据校验。
- 默认关闭（保持本地优先），用户可开。

**M4（一致性基准）**
- 建立 `scoring.consistency.test.ts`：固定输入跑 A 层 100 次断言全相同；跑"A+B"断言 ICC ≥ 0.85。
- 纳入 CI，防止 B 层退化主分一致性。

### 第六章结论与建议

✅ 方案**高可行**，核心已落地，剩余为"补缺+加闸"。  
💡 建议优先级：M2（依据闸，安全性最高）> M1（通道二因子化，价值最高）> M4（基准）> M3（实时检索，可选）。所有改动遵循"增强不替代"范式与"删除须确认"约定，纯增量。

## 第十二章 开发经验沉淀（决策理由与核心洞察）

### 12.1 关键决策理由
1. **双通道而非单源**：通道一保时效、通道二保信噪比与隐私；单源任一失效即盲区。
2. **因子骨架(A)优先于 LLM(B)**：金融评分需可审计/可复现，A 锁定主干，B 只做受控补充。
3. **增强不替代**（沿用 `LLMScoreEnhancer`）：LLM 永远在 A 层之上做增量，从架构杜绝纯 LLM 不一致。
4. **依据追溯闸(M2)**：B 的补充必须附可追溯引用，否则回退 A 层——把"灵活"锚定为"可信"。
5. **本地优先**：IndexedDB + 本地密钥，契合个人工具合规底线，零强制上云。

### 12.2 核心洞察
- **先做现状基线再设计**：本方案与 V9 现有 `LLMScoreEnhancer` / `LocalDoc` 高度吻合，证明"检索核实现有代码"可避免重复造轮子、让方案立刻可落地。
- **文档先行降低返工**：数据字典→DDL→蓝图→架构 逐层细化且交叉校验，实体命名全程一致，后续编码只需"翻译"文档。
- **不新建文档的纪律**：聚焦单一方案文档 + 更新既有文件，避免文档散落失焦（本轮明确要求）。

### 12.3 交叉校验记录
| 维度 | 一致性 |

| 数据字典实体 ↔ DDL store | ✅ 14 实体全覆盖，新增 FactorHint/Citation 对应 factor_hints/citations |
