## 三、阻断项深挖（audit:hardcode 59 处）

人工核验 `npm run audit:hardcode` 原始输出，59 处违规**全部为 `category: "静默回退"`**，模式为 `?? ''` / `?? 0` / `|| ''` 等防御性默认值。样例：

| file:line | 代码 | 性质 |
|-----------|------|------|
| `src/components/ui/ErrorState.tsx:111` | `errorMessage \|\| '发生了未知错误'` | 错误兜底文案（合理） |
| `src/cockpit/widgets/HotSectorWidget.tsx:102` | `(value ?? 0) * 20` | 数值兜底（合理） |
| `src/components/analysis/news/NewsSentimentTrend.tsx:136` | `errorProps={{ error: error ?? '' }}` | 空对象兜底（合理） |
| `src/components/input/StockSearch.tsx:144` | `placeholder \|\| '搜索股票'` | 占位文案兜底（合理） |
| `src/components/system/EngineStatusCard.tsx:128` | `startedAt ?? 0` | 时间戳兜底（合理） |

**结论**：这些不是质量缺陷，是稳健写法。`audit:hardcode` 规则将"静默回退"等同于"硬编码"过于严格。**建议**：在该审计脚本中为 `?? 0` / `?? ''` / `|| 兜底文案` 增加白名单或降级为 Warning，避免阻塞合并。

## 六、Skill 测试反馈（门禁器可优化点）

本次调用同时验证了 Skill 自身，暴露 3 处门禁脚本可改进项（均为**误报**，不影响工程实际质量，但影响信噪比）：

1. **`audit:hardcode` 对静默回退过度敏感** → 建议加白名单/降级 Warning（阻断项本质误报）。
2. **`event-listener-cleanup` 启发式漏识别"订阅返回值清理"模式**（`taskScheduler.subscribe()` 返回 `unsubscribe` 函数并在 cleanup 调用）→ 应扩展识别 `xxx.subscribe` 返回值 + return 清理范式。
3. **`ui-hardcoded-colors` 启发式含误报** → 建议排除 `*.test.ts(x)` 与 `**/statusColors.ts` 等令牌定义文件（92 处中相当比例为测试与令牌本身）。

**总体**：Skill 端到端可工作、可断言、能产出可信信号，且具备自我改进价值。
