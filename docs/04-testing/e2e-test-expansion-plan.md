## 2. 扩展策略

### 2.1 分层覆盖模型

```
┌─────────────────────────────────────┐
│  用户旅程测试（5 条核心路径）        │  ← 最高优先级
│  端到端完整流程验证                  │
├─────────────────────────────────────┤
│  模块功能测试（按舱划分）            │  ← 当前主要部分
│  各舱室功能点验证                    │
├─────────────────────────────────────┤
│  视觉回归测试（30+ 场景）           │  ← UI 一致性保障
│  页面级视觉 diff                    │
├─────────────────────────────────────┤
│  专项测试（响应式/可访问性/性能）    │  ← 质量维度
│  跨维度质量验证                     │
└─────────────────────────────────────┘
```

### 2.2 优先级原则

1. **用户旅程优先**：先覆盖真实用户的完整使用路径
2. **核心功能其次**：再补齐各模块的关键功能点
3. **异常场景补充**：然后覆盖错误、空状态、边界情况
4. **质量维度收尾**：最后补充跨浏览器、性能、可访问性

## 3. 分阶段执行计划

### 3.1 第一阶段：用户旅程（第 1 周）— P0

**目标**：覆盖 5 条核心用户旅程，验证端到端流程

| 编号 | 测试场景 | 路径 | 优先级 |
| :--- | :--- | :--- | :--- |
| J1 | 新用户首次使用 | 首页 → 输入舱 → 添加股票 → 评分 → 查看结果 | P0 |
| J2 | 周末选股研究 | 热门板块 → 加入候选池 → 批量评分 → 筛选排序 → 导出 | P0 |
| J3 | 交易复盘流程 | 持仓 → 添加交易 → 写复盘笔记 → 查看历史 | P0 |
| J4 | 策略回测验证 | 选择策略 → 配置参数 → 运行回测 → 查看结果 → 保存 | P1 |
| J5 | V6 数据迁移 | 总控舱 → 迁移工具 → 上传文件 → 验证数据 → 确认 | P1 |

**J1：新用户首次使用**
- 从首页 / 驾驶舱开始
- 导航到输入舱
- 添加 3 只股票到候选池
- 一键评分
- 查看评分详情
- 验证数据正确展示

**J2：周末选股研究**
- 打开热门板块
- 从板块添加 10 只股票到候选池
- 全量评分
- 按评分排序
- 筛选 top 5
- 导出评分结果（JSON/CSV）
- 验证导出数据正确

**J3：交易复盘流程**
- 添加持仓股票
- 记录买入交易
- 运行评分
- 写交易复盘笔记
- 查看历史复盘记录
- 验证数据一致性

## 5. 测试数据策略

### 5.1 Fixtures 分层

| 层级 | 用途 | 数据量 |
| :--- | :--- | :--- |
| **冒烟数据** | 快速验证核心流程 | 5-10 只股票、基础评分 |
| **标准数据** | 常规功能测试 | 50 只股票、完整评分、交易记录 |
| **大数据集** | 性能 / 边界测试 | 500+ 只股票、大量历史数据 |

### 5.2 数据隔离原则

1. 每个测试套件使用独立的测试数据
2. 测试前清空相关数据，测试后不残留
3. 使用 Mock 服务隔离外部依赖（LLM、行情 API）
4. 关键测试使用独立的 browser context

## 7. 执行命令速查

```powershell
# 本地运行所有 E2E
npm run test:e2e

# UI 模式调试
npm run test:e2e:ui

# 只跑冒烟测试（核心路径）
npx playwright test --grep "@smoke"

# 视觉回归
npm run test:e2e:visual

# 更新视觉基线
npm run test:e2e:visual:update

# Docker 环境视觉回归（CI 用）
npm run test:e2e:visual:docker

# 生成 HTML 报告
npx playwright show-report

# 特定文件运行
npx playwright test e2e/journey-weekend-research.spec.ts

# 追踪调试
npx playwright test --trace on
```
