## 一、可行性分析结论

### 1.1 兼容性矩阵（V6 参考 vs V9 现状）

| 维度 | v6-pro-cockpit（参考） | V9 现状 | 兼容性 |
|---|---|---|---|
| ACL 引擎 `acl.ts` | `check()` 返回 `AclCheckResult`；`assert()` 抛 `AclDeniedError`；`wrap()` 包装 | `assert()` 抛 `AclError`；无 `check/wrap` | ✅ 子集，对齐为**加法无破坏** |
| RBAC 领域模型 | 无 | 5 表 + 审计日志（rbac.types，134 行） | ✅ V9 更完整 |
| 建表迁移 | 无 | `rbacMigrationV24`（6 个 ObjectStore，与领域模型一致） | ✅ 已一致 |
| 阈值/角色常量 | 无 | `rbacThresholds.ts`（含 `BUILT_IN_ROLES`/`PERMISSION_NAMESPACE`） | ✅ 已就绪 |
| 数据层接线 | 无 | `dbConfig` 已有 6 个 `rbac*` STORE_NAME + 6 个 `saveRbac*` ENVELOPE_ACTION + `queryByIndex` | ✅ 已就绪，无冲突 |
| 路由/按钮权限闸 | 无 | `routeGuard.tsx` **已接入 App.tsx**（每路由 `<RouteGuard>` 包裹），注册 trading/command/analysis 按钮权限 | ✅ 已激活 |
| 回收服务 | 无 | `permissionRevocationService.ts`（974 行，完整类型清洁） | ⚠️ **孤立未启动** |

### 1.2 兼容性结论
**可行。** V9 的 RBAC 基础实际上优于 v6 参考实现，数据层、Schema、阈值、路由闸均已就位且无冲突。核心缺口只有两点：
1. **acl 引擎未对齐 v6 参考**（缺 `check()`/`wrap()`，仅 `assert()`）；
2. **回收服务未接线到应用生命周期**（实例化但从未 `start()`，僵尸/过期回收永不触发）；
3. （按您所述领域）赛道对话的权限闸尚未显式登记。

### 1.3 潜在冲突点
- **Error 类命名**：v6 用 `AclDeniedError`，V9 用 `AclError`。建议**复用 V9 既有 `AclError`**，避免全仓引用改动（churn）。
- **bootstrap 启动顺序**：`permissionRevocationService.start()` 必须晚于 `db.init()`（服务经 databridge 查库）；`bootstrapService.initializeApp()` 是天然接入点。
- **后台定时任务**：`setInterval` 在测试/SSR 环境需可注入或 mock，避免泄漏。
- **9 个真实 tsc 错误（非 RBAC）**：若不修，则 `npm run tsc:prod` 整体仍红；它们是交付"可构建集成"的实际阻断项（见 §三）。

## 二、分步实施计划

> 依赖关系自上而下；风险等级标注于每步。验证统一在 Step 6 质量门禁。

### Step 1 — acl.ts 对齐 v6 参考（风险：低）
- **内容**：在 `src/core/acl.ts` 中**加法**引入 `AclCheckResult` 接口与 `check(input): AclCheckResult`、`wrap<T>(input, op)` 方法，复用既有 `AclError`；`assert()` 内部委托 `check()`。
- **依赖**：无。
- **风险**：低（纯加法，现有 `assert` 调用方不动）。
- **验证**：`src/core/acl.test.ts` 通过。

### Step 2 — 回收服务接入应用生命周期（风险：中）
- **内容**：在 `bootstrapService.initializeApp()` 的 `db.init()` 之后调用 `permissionRevocationService.start()`；提供对应 `stop()` 钩子（如全局 teardown/热更新场景）。
- **依赖**：Step 1（可选，互不硬依赖）。
- **风险**：中——后台定时器须防重复启动（`running` 标志已具备）、须测试安全（可注入 `start`/`stop` 或在 test env 跳过）。
- **验证**：`permissionRevocationService` 单测（`runOnce()` 返回结构正确）、tsc 清洁。

### Step 3 — 赛道对话权限闸登记（风险：低）
