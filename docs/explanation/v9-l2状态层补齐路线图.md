## 2. 补齐优先级矩阵

评分维度：1-5 分，综合得分 = 业务价值 × 跨组件共享需求 × 数据持久化需求。

| 功能/页面 | 业务价值 | 跨组件共享 | 持久化 | 综合分 | 优先级 | 说明 |
|-----------|---------|-----------|--------|--------|--------|------|
| 回测页 | 5 | 4 | 3 | 60 | **P0** | 投资决策核心，结果需跨分析/交易舱共享 |
| 持仓控制（PositionControlWidget） | 5 | 5 | 4 | 100 | **P0** | 交易舱与 Cockpit 多处依赖，必须实时同步 |
| 热门板块 | 4 | 4 | 3 | 48 | **P0** | 已在页面接入，但 Widget 侧仍走 Context |
| 价值洼地 | 4 | 4 | 3 | 48 | **P0** | 同上，且与轮动信号强耦合 |
| 策略快照 | 5 | 3 | 5 | 75 | **P0** | 历史快照需持久化，支持回测对比 |
| 个股分析 | 4 | 3 | 3 | 36 | **P1** | 单页使用，但参数化路由需共享 |
| 行业评分 | 3 | 3 | 4 | 36 | **P1** | LLM 评分结果需持久化 |
| 智能评分 | 3 | 3 | 4 | 36 | **P1** | 同上 |
| 本地知识库 | 3 | 2 | 4 | 24 | **P1** | IndexedDB 已持久化，但 UI 状态未收敛 |
| 文档评分 | 3 | 2 | 3 | 18 | **P1** | 低频页面，共享需求低 |
| 纯展示性 Hub 页面 | 2 | 1 | 1 | 2 | **P2** | `AnalysisHubPage`, `TradingHubPage`, `InputHubPage`, `CommandHubPage`, `HomePage` |

### 优先级定义

| 优先级 | 标准 | 处理策略 |
|--------|------|---------|
| **P0** | 综合分 ≥ 45 且为交易/分析核心链路 | 立即改造，纳入当前 Sprint |
| **P1** | 综合分 18-44，有持久化或共享需求 | 排入下一阶段，分批次迁移 |
| **P2** | 综合分 < 18，纯导航/展示 | 最后处理，仅在必要时接入 Store |

## 4. 状态管理规范

### 4.1 Store 目录与命名

- 所有 Store 统一放在 `src/store/`。
- Store 文件名使用 camelCase，如 `backtestStore.ts`。
- Hook 命名必须为 `useXxxStore`，如 `useBacktestStore`。
- 每个 Store 必须导出对应的 TypeScript 类型定义（State + Actions）。

### 4.2 订阅生命周期

- **必须**提供 `initXxxStoreSubscriptions(): () => void` 显式订阅函数。
- **必须**提供 `destroyXxxStoreSubscriptions(): void` 清理函数（或在 `init` 返回的 cleanup 中统一处理）。
- **禁止**在模块顶层调用 `initXxxStoreSubscriptions()` 等副作用；统一由 `main.tsx`、路由入口或组件 `useEffect` 触发。
- 对于多事件订阅，使用数组收集 unsubscribe 函数，参考现有 `agentStore.ts` / `widgetStore.ts` 模式，但需移除其模块级 `initXxxSubscriptions()` 调用。

### 4.3 副作用与数据获取

- Store action 中可直接调用 Service / dataLayer，但禁止在模块加载时执行异步 I/O。
- DataBridge 订阅回调中禁止直接修改 React 组件状态，只能通过 Store actions 更新 state。
- 订阅事件触发频繁时，需在 action 内部做防抖/节流，或增加 `lastUpdated` 时间戳避免重复计算。

### 4.4 Selector 使用

- 组件中优先使用 selector 订阅细粒度状态，避免 `const { ... } = useXxxStore()` 导致整树重渲染。
- 推荐写法：

```tsx
const config = useBacktestStore((s) => s.config)
const results = useBacktestStore((s) => s.results)
const runBacktest = useBacktestStore((s) => s.runBacktest)
```

- 复杂 selector 可抽取为独立函数，放在 `src/store/selectors/` 下。

### 4.5 状态结构

- 每个 Store 必须将 **数据层** 与 **UI 层** 状态分离：
  - 数据层：`data` / `loading` / `error` / `lastUpdated`
  - UI 层：`selectedItem` / `filter` / `sort` / `expandedId` / `modalOpen`
- 需要持久化的状态（如收藏、筛选条件）通过 IndexedDB 或 DataBridge 写入，禁止直接操作 `localStorage`（已有旧数据迁移除外）。

### 4.6 类型安全

- Store State 接口必须显式声明，禁止 `any`。
- Action 返回类型必须明确，异步 action 返回 `Promise<void>` 或定义好的结果类型。
- 新增 Store 后必须补充对应单元测试。

### 8.3 动态分析引擎说明

`IntelligentScoreStore` 与 `IndustryScoreStore` 的 hook 重构采用 **纯常量导出模式**，即原 hook 中的动态逻辑迁移至 Store action，hook 层仅保留纯配置常量（如评分维度权重、行业分类映射等）的导出。这种模式的优势：

1. **可测试性提升**：Store action 可独立单测，无需渲染 React 组件
2. **状态收敛**：评分计算结果存储在 Store 中，支持跨组件共享
3. **渲染优化**：页面组件仅通过 selector 订阅所需切片，避免不必要的重渲染
