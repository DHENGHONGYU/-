## 一、现有报告能力现状

### 1.1 当前报告系统（`scoreDocService.ts`）

| 维度 | 现状 | 20页报告需求 | 差距 |
|:---|:---|:---|:---|
| **报告长度** | ~500-1000 字符（约1-2页） | ~15,000-25,000 字符（约20页） | **20-50倍** |
| **数据覆盖** | 仅评分结果（V6综合分 + 维度分） | 需覆盖：公司概况/行业/财务/估值/技术/舆情/研报/评分/策略/风险/建议 | **全覆盖** |
| **内容深度** | 结构化数字 + 简短理由 | 需：叙事分析/对比分析/趋势图表/风险提示/投资建议 | **深度分析** |
| **生成方式** | 模板拼接（`buildReportMarkdown`） | 需：LLM 深度分析 + 数据可视化 + 人工校对 | **智能生成** |
| **输出格式** | Markdown 纯文本 | 需：Markdown + 图表 + 数据表格 + 导出 PDF | **富媒体** |
| **版本管理** | 按版本号递增（`ScoreDocVersion`） | 需：按日期/触发原因/分析师标记版本 | **多维度** |
| **跨标对比** | 支持两只标最新评分对比 | 需：行业对比/产业链对比/竞品分析 | **横向分析** |

### 1.2 现有报告内容示例（`buildReportMarkdown` 输出）

```markdown
# 贵州茅台（600519.SH）评分报告 V1

  ...

## 二、20页研究报告的数据需求模型

### 2.1 报告章节结构与数据映射

一份 20 页的研究报告，按投研行业标准，需要包含 15 个章节。每个章节对应的数据源和计算需求如下：

```
┌──────────────────────────────────────────────────────────────────────────────┐
│  20页研究报告数据需求模型（40只标的股票池，单份报告）                          │
├──────────────┬─────────────────────────────┬──────────────┬──────────────────┤
│ 章节         │ 数据源                      │ 数据量(估算) │ 计算需求         │
├──────────────┼─────────────────────────────┼──────────────┼──────────────────┤
│ 1. 封面/摘要  │ 元数据 + 综合评分            │ 1 KB         │ 聚合             │
│ 2. 公司概况   │ stocks + 行业分类            │ 2 KB         │ 查询             │
│ 3. 行业分析   │ industry_scores + sector_   │ 5 KB         │ 行业评分 + 产业链 │
│              │ definitions + industryChain   │              │                  │
│ 4. 财务分析   │ FinancialReport + 三表数据   │ 10 KB        │ 财务比率计算      │
│ 5. 估值分析   │ PE/PB/PEG + 行业基准分位     │ 5 KB         │ 分位数计算        │
│ 6. 技术面     │ DailyQuotes (K线) + 指标    │ 8 KB         │ MA/MACD/RSI等    │
│ 7. 资金流向   │ 资金流向数据 + 筹码分布       │ 5 KB         │ 资金分析          │

│ 12. 历史对比  │ score_history (时间序列)     │ 8 KB         │ 趋势分析          │

│ 14. 风险提示  │ 所有风险汇总 + 严重程度      │ 3 KB         │ 风险聚合          │

│ 附录：审计日志│ audit_trails + research_logs │ 3 KB         │ 审计展示          │
├──────────────┴─────────────────────────────┴──────────────┴──────────────────┤
│ 单份报告总计：约 20,000-25,000 字符（40-50 KB）                                │

### 2.2 存储规模冲击

| 场景 | 报告频率 | 单份大小 | 年存储量 | 3年存储量 |
|:---|:---|---:|---:|---:|
| 40只标的，每周1份 | 40 × 52 = 2,080 份/年 | 40 KB | **83 MB** | **250 MB** |
| 40只标的，每日1份 | 40 × 365 = 14,600 份/年 | 40 KB | **584 MB** | **1.75 GB** |
| 含图表/图片（base64） | 同上 | 200 KB | **2.9 GB** | **8.7 GB** |
| 全市场扫描（500只） | 每周1份 | 40 KB | **1.04 GB** | **3.1 GB** |

**关键发现**：
- 每日报告模式在3年内会超出浏览器 IndexedDB 的安全容量（~2GB 警告线）
- 即使每周报告，250 MB 也是结构化数据的 250 倍
- **必须有报告生命周期策略**：完整报告 vs 摘要报告 vs 仅保留评分
