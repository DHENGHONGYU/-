# 体系化上线测试检查清单 Skill

> **版本**: v1.0.1 | **更新日期**: 2026-07-13  
> **适用范围**: 前端/全栈项目（React + Vite + Zustand + Tailwind）  
> **对标标准**: Front-End-Checklist / Cortex / CloudBees / 证监会金融规范 / 华泰证券 / 中信证券

---

## 一、执行前准备

1. **确认项目类型**：纯前端 / 全栈 / 移动端 / 桌面端
2. **确认合规口径**：个人工具 / SaaS / 金融产品（决定合规模块深度）
3. **收集基线数据**：运行全部项目审计命令，记录当前状态

## 三、执行时序模板（4周）

```
W1 地基与硬门槛
├── 架构门禁全绿（audit:layers/hardcode/deadcode + tsc）
├── 安全扫描（npm audit + 渗透测试 + 密钥检查）
├── 测试基线全绿（test:clean + e2e 核心路径）
└── 数据层兜底单测

W2 性能与稳定
├── 性能预算建立（Lighthouse CI + bundle-size）
├── 负载测试（k6/Artillery）
├── 24h 稳定性测试 / 内存泄漏验证
├── APM 监控接入
└── 数据一致性验证

W3 兼容 UX 与监控
├── 多浏览器/分辨率实测
├── 告警阈值演练
├── 灰度开关验证
├── 无障碍人工走查
└── CDN 缓存预热

W4 发布与回归
├── 回滚方案真实演练
├── 容灾方案文档
├── 全量回归测试
├── 发布评审
└── 合规文档归档
```

## 五、常见陷阱与教训

1. **分层审计是地基**：不过则下游所有判定无效，必须 W1 最先闭环。
2. **类型错误必须零容忍**：1 个 tsc error 即阻断发布，第三方库升级需回归。本次12个TS2307错误的根因是服务目录重构后新模块未同步创建。
3. **npm audit 不足**：金融行业标准要求 5 项安全测试技术，必须引入 ZAP/CodeQL。
4. **测试排除文件是债务**：每多 1 个排除文件，基线可信度就下降。
5. **性能需要 RUM**：Lighthouse 实验室数据不能替代真实用户监控。
6. **灰度需要开关**：文字描述的灰度策略无法秒级回滚。
7. **数据一致性需双端验证**：客户端对齐不够，还需服务端接收一致性。
8. **长时间稳定性是隐藏风险**：短测试发现不了内存泄漏，需 24h+。
9. **合规必须留痕**：即使豁免，理由也要文档化。
10. **回滚必须演练**：文档 ≠ 可执行，必须真实跑一遍并记录 RTO。
11. **vi.mock STORE_NAME 必须完整**：测试中 mock `dbConfig` 的 `STORE_NAME` 时，必须包含所有被测试代码引用的 store 名。遗漏会导致运行时 `undefined`，引发级联错误（如 `quotes.history.find` 在空数组上调用）。
12. **dataBridge.query mock 必须与 STORE_NAME 实际值对齐**：`STORE_NAME.dailyQuotes` 实际值为 `'daily_quotes'`（带下划线），mock 中若写 `'dailyQuotes'` 会导致不匹配，返回空数组 `[ ]`（truthy），被存入 cache 后触发 `.find is not a function` 错误。
13. **服务目录迁移必须全链路同步**：从 `src/services/fetcher/` 迁移到 `src/services/input/` 时，不仅要新建目标模块，还要同步更新所有调用方的 import 路径、测试 mock 路径、以及 tsconfig 的 include 范围。漏一步即导致 tsc 批量 TS2307 错误。
14. **区分 tsc:prod 与 tsc:test 的修复优先级**：`tsc:prod`（生产代码）必须零容忍零错误；`tsc:test`（测试+脚本）错误可能更多（当前 ~393），应分批处理，不阻塞生产构建。
