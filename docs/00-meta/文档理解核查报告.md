## 二、四维度理解核查（含证据与缺口）

### 2.1 维度一：整体架构设计 —— 充分

**已确认的核心要点（证据链完整）：**

1. **分层架构（L0–L8 与目录分层双模型）**
   - 目录分层（`AGENTS.md` §一）：`config/core/data/lib/services/store/pages/components/portal/constants` + `types/agents`，并明确**依赖方向**（pages/components→store/services；store→services/core；services→core/data/lib白名单；lib→core/config；core 与 config 互不向下依赖）。
   - 引擎分层（`AGENTS.md` §六 + `05-engine-specs.md` §一）：L3 为纯业务计算层（评分/信号/风控/数据融合）；L0/L1/L2/L5/L6 为 LLM 可增强层，L3/L4/L7/L8 为确定性层；L4 应用层不得直连 L6 外部依赖。
2. **三级加载链（路由→门户→分发器→页面）**
   - `routes.ts`（62 条，`ROUTE_REGISTRY`）→ `PortalShell`（`src/portal/`）→ `{Cabin}App` 分发器（`src/apps/{cabin}/`）→ `src/pages/{cabin}/*Page.tsx`（已实际验证目录存在）。
3. **数据层架构**
   - IndexedDB 自管（`src/data/db-schema.ts` 基线 29 store + migration 增量 RBAC 6 表）；写操作统一经 `DataBridge.forward()` + `ENVELOPE_ACTION`；ACL 矩阵（`dbConfig.ts`）+ MCP ACL 矩阵（`mcpAclMatrix.ts`）纵深防御。
4. **驾驶舱子系统架构**
   - `ARCHITECTURE.md`：React-Grid-Layout 可拖拽 Widget 框架；`MarketDataProvider` + `useMarketData()` 统一注入；`TaskScheduler` + `Collector`（Mock/REST/WebSocket）采集；`MarketDataAdapter` 标准化；注册中心 `widgetRegistry.ts`。

**缺口与待深究：**
- ⚠️ **缺单一「架构总览」整合文档**：架构知识分散在 AGENTS.md（契约）、ARCHITECTURE.md（仅驾驶舱子系统）、06-routing-specs（路由）、05-engine-specs（引擎）、v9-system-blueprint（需求级）。`docs/architecture/` 目录仅含 `v9-mcp-analysis.html`（MCP 专项），无全局 overview。
- ⚠️ **React 版本文档漂移**：`ARCHITECTURE.md` §1.1 写明「React 18」，但 `package.json` 实际为 `react ^19.0.0`（见 §四）。
- 引擎 L0–L8 的**逐层→具体服务映射**需通读 `05-engine-specs.md` 全文方能 100% 对应（当前已确认分层语义与 Fetcher/DataFusion 两引擎）。
