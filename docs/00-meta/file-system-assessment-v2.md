## 8. 整改方案

### 8.1 整改优先级

| 优先级 | 任务 | 预期收益 | 风险 |
|--------|------|----------|------|
| P0 | 统一 docs/ 分类体系 | 消除混乱，提升文档查找效率 | 中 |
| P0 | 清理 scripts/ 根级别文件 | 提升脚本可维护性 | 中 |
| P1 | 建立命名规范文档 | 统一团队规范 | 低 |
| P1 | 修复文档-代码引用漂移 | 提升文档准确性 | 中 |
| P2 | 完善文档导航体系 | 提升文档可用性 | 低 |
| P2 | 建立自动化门禁 | 防止问题复发 | 低 |

### 8.2 详细实施计划

#### 阶段一：docs/ 分类体系统一（P0）

**目标**：将编号分类体系迁移到 Diátaxis 体系

**步骤**：
1. 分析现有文档归属关系
2. 建立映射表：编号目录 → Diátaxis 目录
3. 创建重定向脚本，保持旧链接可用
4. 迁移文档并更新内部引用
5. 归档旧编号目录

**映射规则**：
| 编号目录 | Diátaxis 目标 |
|----------|---------------|
| 00-meta/registry-index.md | docs/README.md |
| 00-meta/ | reference/meta/ |
| 02-design/ | explanation/design/ |
| 04-testing/ | how-to/testing/ |
| 06-project-management/ | reference/project/ |
| 07-archive/ | archive/ |

#### 阶段二：scripts/ 文件分类（P0）

**目标**：统一 scripts/ 文件分类，消除根级别文件与子目录的分类重叠

**风险评估**：直接移动脚本文件会导致内部相对路径引用失效（如 `../src/config/routes.ts`、`./_debug/_audit-pipeline`），因此采用**符号链接方案**而非物理移动。

**步骤**：
1. 分析根级别文件功能和内部引用关系
2. 建立分类规则
3. 在子目录中创建符号链接指向根级别文件
4. 更新 package.json 中的脚本路径指向符号链接
5. 验证所有脚本可正常运行

**分类规则**：
| 前缀/关键词 | 目标目录 | 处理方式 |
|-------------|----------|----------|
| audit- | scripts/audit/ | 符号链接 |
| verify- | scripts/verify/ | 符号链接 |
| generate- | scripts/generate/ | 符号链接 |
| fix- | scripts/fix/ | 符号链接 |
| build- | scripts/build/ | 符号链接 |
| migrate- | scripts/migrate/ | 符号链接 |
| monitor- | scripts/monitor/ | 符号链接 |
| security- | scripts/security/ | 符号链接 |

**符号链接方案优势**：
- 保持根级别文件不动，避免内部相对路径引用失效
- 通过符号链接实现逻辑分类
- 迁移过程可逆，易于回滚
- package.json 路径统一指向子目录，提高可维护性

#### 阶段三：命名规范建立（P1）

**目标**：制定并推广统一的命名规范

**步骤**：
1. 编写命名规范文档
2. 创建命名检查脚本
3. 在 CI/CD 中添加门禁
4. 逐步修复现有问题

**规范要点**：
- 文件名：全小写，连字符分隔（kebab-case）
- 目录名：全小写，连字符分隔
- 组件名：帕斯卡命名（PascalCase），文件名与组件名一致
- 类型定义：后缀为 `.types.ts`
- 测试文件：后缀为 `.test.ts` 或 `.spec.ts`

#### 阶段四：引用验证机制（P1）

**目标**：建立文档与代码引用的自动验证

**步骤**：
1. 创建引用扫描脚本
2. 在 CI/CD 中添加验证步骤
3. 定期运行并修复漂移问题

#### 阶段五：文档导航完善（P2）

**目标**：提升文档的可发现性

**步骤**：
1. 创建 docs/README.md 作为统一入口
2. 建立文档目录树
3. 添加文档搜索功能

## 11. 结论

V9 文件系统当前处于 **中等水平（68/100）**，存在以下主要问题：

1. **docs/ 双分类体系并存** - 需要统一为 Diátaxis 体系
2. **scripts/ 根级别文件过多** - 需要按功能分类
3. **命名风格不一致** - 需要制定统一规范

### 11.1 已完成整改

**阶段一：docs/ 分类体系统一 ✅**
- 将编号分类体系（00-meta, 02-design, 04-testing, 06-project-management, 07-archive）迁移到 Diátaxis 体系
- 创建了 `docs/README.md` 作为统一文档入口
- 创建了重定向文件保持旧链接兼容性
- 更新了 `registry-index.md` 中的路径引用
- 验证：文档审计通过（仅一个预先存在的未文档化文件警告）

### 11.2 执行发现

**scripts/ 分类方案调整**：
在执行阶段二时发现，scripts/ 目录中的脚本文件存在复杂的内部相对路径引用（如 `../src/config/routes.ts`、`./_debug/_audit-pipeline`）。直接移动文件或使用符号链接都会导致这些相对路径失效。

**解决方案**：
采用**文档化分类方案**，即创建分类目录和说明文档，但保持根级别文件位置不变。具体包括：
1. 创建分类目录（audit/, verify/, generate/, fix/, build/, migrate/）
2. 在每个目录中创建 `../../README.md` 说明该分类的脚本列表和用途
3. 更新 package.json 保持原路径不变（或根据实际情况选择性更新）
4. 在代码注释中添加分类标签
