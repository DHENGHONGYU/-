## 一、分类体系总览

### 1.1 三维分类模型

V9 项目文档采用**三维交叉分类体系**，每份文档同时归属三个维度：

```
                    ┌─────────────────────┐
                    │   文档类型（What）    │
                    │  - 参考/解释/指南/教程 │
                    │  - 报告/复盘/规范/契约 │
                    └──────────┬──────────┘
                               │
                    ┌──────────▼──────────┐
                    │  功能属性（Which）    │
                    │  - 前端/后端/数据库   │
                    │  - UI/UX/架构/算法    │
                    └──────────┬──────────┘
                               │
                    ┌──────────▼──────────┐
                    │  开发阶段（When）     │
                    │  - 规划/设计/开发/测试 │
                    │  - 部署/运维/复盘      │
                    └─────────────────────┘
```

### 1.2 三维度关系
| 维度 | 英文 | 含义 | 回答问题 |
|------|------|------|----------|
| **文档类型** | Type | 文档的性质和用途 | 这是什么类型的文档？ |
| **功能属性** | Domain | 文档所属的功能领域 | 文档涉及哪个业务/技术领域？ |
| **开发阶段** | Phase | 文档对应的生命周期阶段 | 在哪个阶段产生/使用？ |

### 1.3 层级结构（4 层）

```
L1 一级分类（大类别）
  └── L2 二级分类（子类别）
        └── L3 三级分类（细分类）
              └── 文档（具体文件）
```

**示例**：
```
参考文档（L1）
  └── 架构规范（L2）
        └── 分层架构（L3）
              └── AGENTS.md（具体文档）
```

## 六、编号系统规范
### 6.1 文档唯一编号格式

**格式**：`V9-DOC-<类型码><阶段码><序号>`

**示例**：
- `V9-DOC-T2D1P2-001`：解释类/架构领域/设计阶段/第 1 号
- `V9-DOC-T5D7P6-003`：报告类/项目管理/复盘阶段/第 3 号
- `V9-DOC-T1D3P3-012`：参考类/后端服务/开发阶段/第 12 号
### 6.2 编号规则详解

| 部分 | 长度 | 含义 | 取值范围 |
|------|------|------|----------|
| `V9-DOC-` | 7 | 项目前缀 | 固定值 |
| 类型码 | 2 | 文档类型（T1-T6） | T1, T2, T3, T4, T5, T6 |
| 领域码 | 2 | 功能领域（D1-D8） | D1, D2, D3, D4, D5, D6, D7, D8 |
| 阶段码 | 2 | 开发阶段（P0-P6） | P0, P1, P2, P3, P4, P5, P6 |
| `-` | 1 | 分隔符 | — |
| 序号 | 3 | 顺序号（同分类下递增） | 001-999 |

### 6.3 编号使用场景

| 场景 | 是否使用编号 | 说明 |
|------|-------------|------|
| 文件名 | ❌ 不使用 | 文件名保持语义化命名（kebab-case） |
| 文档清单 | ✅ 使用 | CSV/Excel 清单中的唯一标识 |
| 文档 Frontmatter | ✅ 使用 | `doc_id` 字段 |
| 交叉引用 | ⭕ 可选 | 可用编号或文件名引用 |
| 归档管理 | ✅ 使用 | 归档文件编号追踪 |

### 6.4 编号分配规则

1. **唯一性**：每份文档有且仅有一个编号，编号永久不变
2. **不重用**：删除/归档的文档编号不分配给新文档
3. **顺序分配**：同分类下按创建时间顺序分配序号
4. **批量预留**：大型功能模块可预留号段（如 001-050）
5. **自动生成**：通过脚本工具自动分配和管理编号

## 七、分类标签使用指南
### 7.1 Frontmatter 标准字段

每份文档必须在文件头部包含以下 Frontmatter 字段：
```yaml
---
title: 文档标题
doc_id: V9-DOC-T2D1P2-001     # 文档唯一编号
type: explanation              # T1-T6 类型
domain: architecture           # D1-D8 功能域
phase: design                  # P0-P6 开发阶段
tier: important                # 重要级：important / reference / supporting
code_version: 2.0.0            # 对应代码版本
version: v1.0.0                # 文档版本
last_updated: 2026-07-17       # 最后更新日期
maintainer: 维护者             # 维护负责人
status: active                 # 状态：active / deprecated / draft
tags: [tag1, tag2, tag3]       # 自定义标签
change_log:                    # 变更日志
  - date: 2026-07-17
    author: 作者
    desc: 变更描述
---
```

### 7.2 必填字段 vs 可选字段
| 字段 | 必填 | 说明 |
|------|------|------|
| `title` | ✅ | 文档标题 |
| `doc_id` | ✅ | 文档唯一编号 |
| `type` | ✅ | 文档类型（T1-T6） |
| `domain` | ✅ | 功能域（D1-D8） |
| `phase` | ✅ | 开发阶段（P0-P6） |
| `code_version` | ✅ | 对应代码版本 |
| `version` | ✅ | 文档版本 |
| `last_updated` | ✅ | 最后更新日期 |
| `status` | ✅ | 文档状态 |
| `tier` | ⭕ | 重要级别 |
| `maintainer` | ⭕ | 维护者 |
| `tags` | ⭕ | 自定义标签 |
| `change_log` | ⭕ | 变更日志 |
