## 一、工作流程总览

### 1.1 五阶段工作流

```
┌─────────────────────────────────────────────────────────────┐
│  Phase 1: 盘点与评估                                      │
│  ─────────────────                                      │
│  • 全量文档扫描 → 现状评估 → 问题诊断 → 范围确认            │
│  输出：文档现状报告、整理范围、优先级排序                      │
└────────────────────────────┬────────────────────────────┘
                             ↓
┌─────────────────────────────────────────────────────────────┐
│  Phase 2: 分类与标引                                      │
│  ─────────────────                                      │
│  • 三维分类 → 编号分配 → Frontmatter → 交叉引用            │
│  输出：分类完成的文档、完整元数据、索引目录                  │
└────────────────────────────┬────────────────────────────┘
                             ↓
┌─────────────────────────────────────────────────────────────┐
│  Phase 3: 清理与归档                                      │
│  ─────────────────                                      │
│  • 死文档识别 → 内容审核 → 归档整理 → 目录清理            │
│  输出：归档文档库、归档清单、活跃文档集                    │
└────────────────────────────┬────────────────────────────┘
                             ↓
┌─────────────────────────────────────────────────────────────┐
│  Phase 4: 审核与发布                                      │
│  ─────────────────                                      │
│  • 质量检查 → 交叉验证 → 问题修复 → 正式发布                │
│  输出：质量报告、整理后文档库、发布公告                    │
└────────────────────────────┬────────────────────────────┘
                             ↓
┌─────────────────────────────────────────────────────────────┐
│  Phase 5: 持续维护                                      │
│  ─────────────────                                      │
│  • 日常更新 → 定期审计 → 季度复盘 → 持续优化                │
│  输出：维护日志、健康度报告、改进计划                        │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 角色与职责
| 角色 | 职责 | 参与阶段 |
|------|------|----------|
| **文档管理员** | 整体协调、质量把关、最终审核 | 全阶段 |
| **架构师** | 技术文档审核、架构类文档分类 | Phase 2, 4 |
| **开发代表** | 技术准确性验证、死文档判定 | Phase 3, 4 |
| **产品经理** | 产品类文档审核、需求类分类 | Phase 2, 4 |
| **测试代表** | 测试类文档审核、质量门禁验证 | Phase 4 |

### 1.3 时间估算（800 份文档规模）

| 阶段 | 工作量（人天） | 说明 |
|------|---------------|------|
| Phase 1 | 2 | 盘点扫描 + 评估 |
| Phase 2 | 5 | 分类标引（主力工作） |
| Phase 3 | 3 | 死文档审计 + 归档 |
| Phase 4 | 2 | 质量审核 + 修复 |
| Phase 5 | 持续 | 日常维护 |
| **合计** | **12 人天** | 全量整理 |

## 二、Phase 1：盘点与评估

### 2.1 全量文档扫描

**目标**：获取完整的文档清单和现状数据

**操作步骤**：
| 步骤 | 操作 | 工具/命令 | 产出 |
|------|------|-----------|------|
| 1.1 | 扫描所有文档 | `Get-ChildItem -Recurse -Include *.md | 全量文件列表 |
| 1.2 | 提取元数据 | 脚本解析 Frontmatter | 标题/类型/状态等 |
| 1.3 | 统计分析 | 按目录/类型/大小/日期统计 | 现状统计报告 |
| 1.4 | 生成初稿清单 | 导出 CSV | 初始文档清单 |

**检查点**：
- [ ] 文档数量统计准确（误差 < 1%）
- [ ] 所有目录都已覆盖
- [ ] 归档文档单独统计
- [ ] 非 Markdown 文档单独记录

### 2.2 现状评估

**评估维度**：
| 维度 | 评估内容 | 评估方法 |
|------|----------|----------|
| **完整性** | 缺失文档、孤儿文档、重复文档 | 对比功能清单 + 交叉引用检查 |
| **准确性** | 内容是否与代码一致 | 抽样审核 + 代码对比 |
| **时效性** | 最后更新时间、版本对应性 | 更新时间统计 + 版本对照 |
| **规范性** | Frontmatter、命名、格式 | 规则检查脚本 |
| **可读性** | 结构清晰度、语言表达 | 抽样阅读评估 |

### 2.3 问题诊断

**常见问题分类**：

| 问题类型 | 说明 | 优先级 |
|----------|------|--------|
| 分类混乱 | 文档放错目录、类型不明确 | 高 |
| 命名不规范 | 中文命名、大小写不一、含义模糊 | 高 |
| 死文档 | 过时、废弃、无引用 | 高 |
| 重复文档 | 内容重复、多版本并存 | 中 |
| 元数据缺失 | 无 Frontmatter、信息不全 | 中 |
| 内容过时 | 与当前代码/功能不一致 | 中 |
| 格式混乱 | Markdown 不规范、排版差 | 低 |

### 2.4 范围确认与优先级

**整理范围确认**：
- [ ] 确认需要整理的文档总数
- [ ] 确认不需要整理的文档（如自动生成、外部导入）
- [ ] 确认归档标准和判定规则
- [ ] 确认时间范围和里程碑

**优先级排序（MoSCoW 方法）**：
- **Must Have**：核心参考文档、架构文档、用户指南
- **Should Have**：设计文档、报告、教程
- **Could Have**：历史报告、会议记录、草稿
- **Won't Have**：临时文件、测试输出、自动生成

## 三、Phase 2：分类与标引

### 3.1 三维分类

**分类依据**：[文档分类体系规范](document-classification-system.md)

**操作步骤**：
| 步骤 | 操作 | 说明 |
|------|------|------|
| 2.1 | 确定文档类型（T1-T6） | 参考/解释/指南/教程/报告/元文档 |
| 2.2 | 确定功能域（D1-D8） | 架构/前端/后端/数据/AI/QA/项目/产品 |
| 2.3 | 确定开发阶段（P0-P6） | 规划/需求/设计/开发/测试/部署/复盘 |
| 2.4 | 打标签（tags） | 自定义关键词标签 |

**分类原则**：
- 每份文档必须归属一个主分类，可多个副标签
- 分类不清时，按主要用途归类
- 争议文档由文档管理员裁定
- 分类结果记录在 Frontmatter 中
### 3.2 编号分配

**编号规则**：参考[文档分类体系规范 §6](document-classification-system.md#六编号系统规范)

**编号格式**：`V9-DOC-<类型码><领域码><阶段码>-<序号>

**分配流程**：
1. 按分类结果确定类型码、领域码、阶段码
2. 在同分类下按顺序分配序号
3. 编号永久不变，删除文档编号不重用
4. 记录编号映射关系表
### 3.3 Frontmatter 补齐

**标准 Frontmatter**：参考[文档风格指南 §6](document-style-guide.md#六frontmatter-规范)

**必填字段**：
- [ ] title（文档标题）
- [ ] doc_id（唯一编号）
- [ ] type（文档类型）
- [ ] domain（功能域）
- [ ] phase（开发阶段）
- [ ] code_version（代码版本）
- [ ] version（文档版本）
- [ ] last_updated（最后更新）
- [ ] status（状态）

### 3.4 交叉引用检查
**检查内容**：
- [ ] 文档是否被索引收录
- [ ] 文档是否引用了相关文档
- [ ] 被引用文档是否存在
- [ ] 链接路径是否正确

**修复动作**：
- 补充缺失的引用链接
- 修复失效的链接
- 添加反向引用
- 更新目录索引

## 四、Phase 3：清理与归档

### 4.1 死文档识别

**判定标准（满足任一即可判定）**：
| 判定条件 | 说明 | 权重 |
|----------|------|------|
| **开发团队确认** | 负责人确认不再需要更新 | 决定性 |
| **无交叉引用** | 没有任何活跃文档引用它 | 重要 |
| **版本过旧** | 超过 2 个大版本未更新 | 参考 |
| **被新文档替代** | 有更新更完整的文档替代 | 决定性 |
| **功能已移除** | 对应功能已从代码中删除 | 决定性 |
| **临时文档** | 会议记录、临时方案、草稿 | 参考 |
| **重复内容** | 与其他文档内容高度重复 | 重要 |

**识别方法**：
1. 脚本初筛（更新时间、引用次数）
2. 人工复核（按领域分组审核）
3. 开发确认（负责人签字确认）
4. 最终裁定（文档管理员终审）

### 4.2 归档标准

**归档等级**：

| 等级 | 说明 | 保存位置 | 可访问性 |
|------|------|----------|----------|
| A 级 | 重要历史文档，可能需要查阅 | `archive/important/` | 正常访问 |
| B 级 | 普通历史文档，保留备用 | `archive/normal/` | 正常访问 |
| C 级 | 草稿/临时，基本不用 | `archive/drafts/` | 低优先级 |

**归档标注要求**：
- 归档文档保留原目录结构
- 添加归档标记（Frontmatter 中 status: archived）
- 记录归档原因和归档日期
- 在归档清单中登记

### 4.3 重复文档处理

**重复类型**：
- 完全重复：内容 100% 相同
- 高度相似：内容 > 80% 相同
- 版本重复：同一文档的不同版本

**处理策略**：
- 完全重复 → 保留最新版本，删除重复
- 高度相似 → 合并为一份，归档其他
- 版本重复 → 保留最新活跃版，旧版归档
### 4.4 目录整理

**整理动作**：
| 动作 | 说明 |
|------|------|
| 移动 | 文档放到正确的分类目录 |
| 重命名 | 按命名规范修改文件名 |
| 合并 | 重复/相似文档合并 |
| 拆分 | 过长文档按主题拆分 |
| 归档 | 死文档移入 archive |
| 删除 | 确认无用的文档删除 |

**注意事项**：
- 移动文档必须更新所有引用链接
- 重命名必须更新索引和清单
- 合并必须保留变更历史
- 删除必须有确认记录

## 五、Phase 4：审核与发布

### 5.1 质量检查

**检查清单**：

| 检查项 | 检查方法 | 通过标准 |
|--------|----------|----------|
| 分类准确性 | 抽样审核 20% 文档 | 准确率 ≥ 95% |
| 编号唯一性 | 脚本检查重复编号 | 0 重复 |
| Frontmatter 完整度 | 脚本检查必填字段 | 完整率 ≥ 98% |
| 链接有效性 | 脚本检查死链接 | 死链接 < 1% |
| 命名规范性 | 脚本检查命名规则 | 合规率 ≥ 95% |
| 目录完整性 | 对比功能清单 | 核心文档无遗漏 |
| 归档准确性 | 审核归档清单 | 无误归档 |

### 5.2 交叉验证

**验证维度**：
- 文档 ↔ 代码：核心功能是否都有文档
- 文档 ↔ 文档：交叉引用是否正确
- 目录 ↔ 索引：目录结构是否与索引一致
- 清单 ↔ 实际：CSV 清单是否与实际文件一致
### 5.3 问题修复

**修复优先级**：
- P0：分类错误、编号重复、死链接 → 立即修复
- P1：Frontmatter 缺失、命名不规范 → 尽快修复
- P2：格式问题、排版优化 → 择机修复

**修复流程**：
1. 记录问题清单
2. 按优先级排序
3. 分配修复责任人
4. 修复后重新验证
5. 确认关闭问题

### 5.4 正式发布

**发布清单**：
- [ ] 所有质量检查通过
- [ ] 所有 P0/P1 问题已修复
- [ ] 文档清单已更新
- [ ] 目录索引已更新
- [ ] README 入口已更新
- [ ] 归档目录已就绪
- [ ] 发布公告已撰写
- [ ] 团队通知已发送

## 六、Phase 5：持续维护
### 6.1 日常维护

**日常操作**：

| 频率 | 操作 | 责任人 |
|------|------|--------|
| 每次新增文档 | 按规范命名、补 Frontmatter、加入清单 | 文档作者 |
| 每次修改文档 | 更新版本号、变更日志 | 文档作者 |
| 每周 | 文档健康度快速检查 | 文档管理员 |
| 每月 | 死文档识别、归档清理 | 文档管理员 |
| 每季度 | 全量审计、整理复盘 | 全体参与 |

### 6.2 定期审计

**季度审计内容**：
- 文档数量变化统计
- 分类准确性抽检
- 时效性检查
- 死文档识别
- 健康度评分

**审计输出**：
- 文档健康度报告
- 问题清单与改进计划
- 下季度维护计划

### 6.3 文档健康度指标

| 指标 | 计算方法 | 目标值 |
|------|----------|--------|
| 文档覆盖率 | 有文档的功能 / 总功能数 | ≥ 90% |
| 更新及时率 | 30 天内更新的核心文档 / 核心文档总数 | ≥ 80% |
| 分类准确率 | 分类正确的文档 / 抽检文档数 | ≥ 95% |
| 链接有效率 | 有效链接 / 总链接数 | ≥ 99% |
| Frontmatter 完整率 | 完整 Frontmatter / 总文档数 | ≥ 95% |
| 死文档率 | 死文档 / 总文档数 | ≤ 10% |
