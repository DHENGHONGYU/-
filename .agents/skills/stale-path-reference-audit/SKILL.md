# 失效路径引用审计（僵尸链接检测与整改） — v1.0.0

> 核心目标：消除因文件迁移/改名/删除（及选择性提交导致文档丢失）产生的"僵尸链接"——它们不会立刻报错，
> 但会让脚本静默失效、文档门禁误报、读者点进死链。
> 真实事故基线：A 类代码/脚本硬编码路径失效 559 处、C 类文档链接失效 1275 处（含迁移型 341 + 丢失型 934）。

---

## 一、触发条件

- 文件重梳后核对：迁移/改名/删除文档或源码后，确认所有引用处已同步
- 排查"脚本引用的文件找不到"：`join(ROOT,...)` / `readFileSync` 指向已迁移/消失的文件而静默失效
- 文档链接大面积失效：交叉核对 docs 内部 `](相对路径)` 链接，区分"迁移"与"丢失"
- 周期性 doc↔code 一致性体检（建议并入 `audit:docs` 门禁）

**与文件迁移 SOP 绑定**：本技能是 `docs/how-to/FILE-MANAGEMENT-GUIDE.md` §6.3 文件迁移 SOP「Step 5 全文件类型残留扫描」的官方检查实现——**迁移 = SOP §6.3 流程约束 + 本技能残留扫描 + `audit:layers` 跨层门禁，三者缺一不可**。
**协作边界**：文档同步治理飞轮 → `doc-code-dual-proofreading`（本技能发现失效 → 用其飞轮机制固化进自动更新闭环）；跨层调用检查由 `audit:layers` 承载，本技能仅聚焦路径失效。

---

## 二、前置检查

| # | 检查项 | 方法 | 通过标准 |
|---|--------|-----|---------|
| 1 | 扫描范围确认 | `src/`、`scripts/`、`docs/`（排除历史报告目录）、`prompts/`、`.husky/`、`AGENTS.md` | 九类文件：`.ts/.tsx/.md/.json/.mjs/.cjs/.yaml/.yml/.sh` |
| 2 | 精度护栏内置 | 排除 `node_modules`/`dist`/`build`/`outputs`/`.venv`/`.git`；`file://` 按真实路径校验；写目标路径（`reports/`/`drafts/`/`e2e/`/测试产物）单独标记**不计入失效读取源**；过滤 HTML 片段/占位示例/乱码行 | 低误报 |
| 3 | Git 大小写陷阱 | Windows 文件系统大小写不敏感、Git 敏感 | 路径大小写必须与目标文件实际一致，否则扫描"存在"但提交后失效 |

## 三、阶段化 SOP

### 四类扫描（优先级 A > B > C > D）

| 类 | 对象 | 破坏性 | 检测方法 |
|----|------|--------|----------|
| A | 代码/脚本硬编码文件路径 | 高 | 正则捕获 `join/resolve(BASE,'lit')`、`readFileSync/open('lit')` → 「文件目录 + 仓库根」双基准 `statSync` 校验 |
| B | 文档触发规则路径（doc-update-trigger.ts TRIGGER_RULES） | 高 | 解析每条规则 `patterns[]`/`docsToUpdate[]`；glob 用 glob 匹配、字面路径用 stat |
| C | 文档内部相对链接 | 中 | 提取 `](rel)` 与 `<rel>`，剥 `#/?` 与外部协议，相对当前 .md 目录解析；`basename` 全仓索引区分"迁移 vs 丢失" |
| D | 注释/docstring 提及的文件 | 中低 | 注释中"见/参考 + 文件名"模式抽取校验，可并入 A 类 |

**双基准解析（降误报）**：相对路径同时以「当前文件目录」与「仓库根」为基准解析，任一存在即判有效。

### 修复模式

1. **重定向表驱动批量替换（首选）**：复用 `docs/_redirect-map.json`（旧→新映射），对 A/C/D 统一重写——仅当旧路径/basename 是映射表**精确 key** 且新目标存在时才改写，避免模糊匹配误伤
2. **递归扫描替代硬编码（根治）**：如 `audit-doc-sync.ts` 改 `collectDocs(DOCS_DIR)` 目录递归 + try/catch 兜底；凡能靠目录遍历覆盖的，不写死具体文件路径
3. **修正基准错误**：根级文件应 `join(ROOT,'package.json')` 而非相对脚本目录；越层 `../../AGENTS.md` 修正相对基准
4. **消失文件处理**：目标确已删除 → 删引用/注释，或改指向现存等价文档，不保留死链

### 整改优先级（基于真实数据）

- **必须修**：A 类 `fs.read/open` 直接读取失效、已确认的真实路径失效（更新路径或修正基准）
- **可分批修**：迁移型用重定向表一次性重写；丢失型先确认目标文档是否补回，再决定删链或补文档
- **可暂挂起**：`docs/archive/` 历史文档（预期高噪音）、样式指南占位示例、乱码行

### 验证飞轮（整改后必跑）

```
重跑四类扫描 → 对比 before/after 失效数 → 重跑 audit:docs 门禁 → 确认无新破坏
```
每类整改后复测不得跳过；A 类重跑受影响脚本确认行为不变；C 类确认失效数下降且无新坏链。

## 四、陷阱与经验教训

| # | 陷阱 | 后果 | 规避 |
|---|------|-----|-----|
| 1 | 文件重梳后不跑此审计 | 失效引用攒到门禁误报才发现 | 任何 `mv`/删除后立即四类扫描 |
| 2 | 代码写死会移动的文档路径 | 知识结构重组即失效 | 目录递归扫描或重定向表，不用字面量 |
| 3 | 选择性提交造成"丢失型"死链 | 改路径修不好 | 先决定文档是否补回，再删链或补档 |
| 4 | B 类触发规则路径不进 CI | 规则静默失效 | 固化进 `audit:docs` 防回归 |
| 5 | 模糊匹配批量替换 | 误伤正常引用 | 仅精确 key + 新目标存在才改写 |
| 6 | **重点核对 `AGENTS.md` 目录描述** | 引用旧目录误导 AI 生成错误代码 | 扫描范围必含 `AGENTS.md` |
