# tsc:test 测试文件类型错误系统性诊断与修复 — v1.0.0

> **核心铁律：测试类型错误 ≠ 业务代码坏了。** 绝大多数是「测试契约」与「源码真实类型」失配（契约漂移），修复点在测试侧，不是源码侧。
> **绝不因测试类型债而放宽源码约束（关 strictNullChecks）或用 `any` 掩盖——那是把债务转嫁给生产。**

---

## 一、触发条件

满足任一即触发：
1. `npm run tsc:test` 退出码非 0，输出集中在 `tests/**` 或 `src/**/*.test.*`
2. 错误数 30+ 且分散在多测试文件（历史测试债）
3. 出现 `TS2305`（找不到导出）/`TS2339`（属性不存在）/`TS2322`（不可赋值）等"测试引用了源码没有的东西"特征码
4. 重构/接口变更后测试批量飘红（契约漂移爆发）

**不触发**：错误全在 `src/**` 非测试源码 → 真 prod 缺陷，走 `module-sync-checklist` + `tsc-gate-scope-audit`。

---

## 二、前置检查

| # | 检查项 | 方法 | 通过标准 |
|---|--------|-----|---------|
| 1 | 严格配置理解 | `tsconfig.test.json` 继承 strict 全家桶（`strict`/`strictNullChecks`/`noUncheckedIndexedAccess`/`noImplicitAny`） | 这些是特意开启的，修复时保留 |
| 2 | 错误清单聚合 | `scripts/tsc-test-inventory.ts` 按文件/错误码分组，输出 Top-N 排查顺序 | 从错误率最高文件开始 |
| 3 | 铁律确认 | 改测试不动源码、禁 `any`/`@ts-ignore`、漂移类必须先读真实源码 | 防二次漂移 |

## 三、阶段化 SOP

### 根因分类模型（五大类）

| 类 | 名称 | 占比 | 特征与修复 |
|---|------|-----|-----------|
| A | **契约漂移** | ≈60% | 测试按"旧契约"写断言：字段改名/删除、类型改名（`'report'`→`'research_report'`）、方法重命名、返回结构变（`null`→`undefined`、数组→`SyncResult`）、枚举值删减。**先读真实源码再改测试** |
| B | 严格空检暴露 | ≈25% | `TS2532/TS18048`：用 `!`（已知非空）或 `?.` 收敛，**不关规则** |
| C | vi.mock 提升陷阱 | ≈10% | 工厂函数提升执行，导入绑定 TS 视为可能未初始化 → 工厂内加 `!`：`dbModule!.db` |
| D | 未使用声明 | ≈5% | `TS6133/TS6196` 删未用；`TS2783` 删被 spread 覆盖的冗余键 |
| E | 脚本替换缺陷 | 偶发致命 | 正则批量修测试吞掉数组下标 → `targets![]!` 触发 TS1011；先全量补 `[0]` 再按语义还原 `[1]/[2]` |

**高危信号**：同一文件多个 TS2339/TS2305 指向"源码听起来该有、实际没有"的符号 → 99% 是漂移，不是源码缺实现。

### 逐文件排查五步法（禁止跳到"直接改"）

1. **定位**：inventory 聚合 Top-N，按错误数降序推进
2. **根因**：每错误归入 A–E 类；漂移类**必须先读真实源码**（如 `src/services/profile/profileService.ts`），逐项比对"测试引用符号"与"源码真实导出"
3. **验证**：用 Grep 在源码搜真实符号名确认拼写与类型；改完仍飘红 → 立即回头重读源码（多半又凭想象补了一处）
4. **修复**：A 改测试对齐真实类型；B 用 `!`/`?.`；C 工厂加 `!`；D 删声明；E 补下标
5. **提炼**：每文件修后一句话记根因+防复发动作，沉淀回本技能模式库

### 高频错误码速查

| 错误码 | 首选归因 | 首选修复 |
|---|---|---|
| TS2305 / TS2307 | A 类漂移 / 路径漂移 | 读源码真实导出名，改测试引用 |
| TS2322 / TS2345 | A5/A6 结构变 | 对齐真实返回类型 |
| TS2339 | A1/A2 字段改名删 | 读源码真实字段名 |
| TS2532 / TS18048 | B 类 | `!` 或可选链 |
| TS6133 / TS2783 | D 类 | 删除 |
| TS1011 | E 类脚本缺陷 | 补回下标数字 |

### 防复发（门禁分流）

- **测试即契约快照**：源码接口变更时同回合改对应测试（配合 `module-sync-checklist` 十域同步）
- `tsc:prod` 与 `tsc:test` 分开跑；测试债爆发只修测试，不动 `tsconfig` 严格度
- 批量脚本三铁律：① 先人工抽样 3 行验证正则输出；② 全量跑完立即 `tsc:test`；③ 用 `replace_all` 减少吞字符风险
- 趋势追踪：`scripts/tsc-test-inventory.ts` 周度快照，错误数回升即预警

## 四、陷阱与经验教训

| # | 陷阱 | 后果 | 规避 |
|---|------|-----|-----|
| 1 | 凭"听起来该有"补全字段 | 二次漂移，修完仍红 | 补字段前先 Grep 源码确认真实名 |
| 2 | 用 `any`/`@ts-ignore` 掩盖 | 债务转嫁生产 | `!`/`?.` 收敛，保留严格约束 |
| 3 | 关掉 `noUncheckedIndexedAccess` | 越界防护丢失 | 保留规则，用 `!` 标注已知非空 |
| 4 | 批量正则不抽样直接全量 | 吞下标字符引发 TS1011 潮 | 先抽 3 行，跑完立刻验证 |
| 5 | 误判漂移为源码缺实现 | 反向改坏源码 | 多符号齐失配 = 漂移信号，读源码裁决 |
