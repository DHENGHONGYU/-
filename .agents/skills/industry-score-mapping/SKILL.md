# 行业评分估值映射 (Industry Score Mapping) — v1.0.7

> **版本**: v1.0.7 | **日期**: 2026-08-21 | **校验基准**: FinSightV9 code_version 2.0.0-rc.1
> **任务性质**: SOP 执行（行业评分→个股L-1层映射），允许读取行业分析报告并注入 V6 L-1，禁止绕过关联度校准直接注入满分，禁止硬编码新行业不更新映射表
> **输出格式**: 阶段化 SOP 矩阵 + 个股L-1评分对象（含行业归属/SKILL-C四维/SKILL-N六维/关联度/L-1综合分）

---

## 一、触发条件（Invoke When · RULE-TPL 三标签标注：显式触发 / 脚本/审计触发 / 设计/协议触发）

- **显式触发 1**：用户明确要求「个股行业评分映射」「SKILL-C」「SKILL-N」「行业匹配」「L-1层注入」；或分析个股需检索行业评分并注入 V6
- **显式触发 2**：核心标的→行业映射表新增股票条目或调整关联度系数；或 `1-细分行业分析报告/` 目录中的预制行业 SKILL 分析报告版本更新需重新缓存评分
- **脚本/审计触发 3**：`v6-stock-analysis-model` 开始执行 L-1 行业评分估值层，上游触发行业评分注入；或 `intelligent-score` 执行个股九维评分缺行业维度时自动触发
- **脚本/审计触发 4**：`npm run audit:skill-coverage` 报映射注册表漂移；或 vitest 中 L-1 评分快照断言不通过
- **设计/协议触发 5**：L-1 层权重公式版本变更、V6 模型层次结构调整后存量映射重评；行业分类体系（7 大行业等）扩展时，映射表与预制报告必须同步扩展

**不触发场景**（减少误激活，至少 2 条）：
- 纯行业层面的七维评分（走 `industry-score`）
- 纯六维度板块轮动信号分析（走 `sector-analysis-framework`）

**协作 Skill（链式调用，至少 1~3 个）**：
- `industry-score`：行业七维评分源数据，若预制报告过时可动态重算
- `v6-stock-analysis-model`：消费本 Skill 输出作为 L-1 层输入
- `intelligent-score`：个股九维评分的行业维度参考
- `audit:skill-coverage`：完成后核验注册完整性

## 三、阶段化 SOP（按 Phase 0~N 组织，**每阶段必写目标 + 交付物清单 + 代码/文档模板**）

### Phase 0 — 个股信息提取与三步匹配检索

**目标**：按「精确代码匹配→关键词匹配→无覆盖标注」三步流程，确定个股所属行业与关联度系数。

**交付物**：
1. **三步匹配流程图**（已在原 SKILL.md §匹配流程中固化）：
   ```
   Step 1 精确代码匹配 → 行业报告核心标的列表 → 关联度 1.0
   Step 2 关键词匹配   → 业务关键词（光模块/创新药/AI 等）→ 关联度 0.5~0.9
   Step 3 无覆盖       → 标注「无行业报告」→ L-1 不纳入
   ```
2. **匹配结果对象**：
   ```typescript
   interface IndustryMatchResult {
     stockCode: string;          // 如 600519.SH
     stockName: string;
     industry: string | null;    // CoWoS先进封装 / 芯片设计 等 7 大行业
     matchStep: 1 | 2 | 3;
     correlationCoefficient: number;  // 1.0 / 0.9 / 0.7 / 0.5
     remark?: string;            // 如「精确匹配核心标的」「关键词匹配创新药」「无行业报告」
   }
   ```

### Phase 1 — SKILL-C/SKILL-N 评分提取

**目标**：从 7 份预制行业报告中提取 SKILL-C（四维：结构稀缺/国产替代壁垒/技术先进/政策契合）与 SKILL-N（六维：下游/轮动信号/技术迁移/基金估值 等）汇总评分。

**交付物**：
1. **七大行业评分速查表**（硬编码为字典，避免反复解析报告）：
   ```
   CoWoS先进封装:  { skillC: 4.90, skillN: 4.83, quadrant: '战略强攻', advice: '极度超配' }
   芯片设计:       { skillC: 4.19, skillN: 4.00, quadrant: '战略强攻', advice: '超配' }
   机器人:         { skillC: 4.14, skillN: 4.17, quadrant: '战略强攻', advice: '超配' }
   量子计算:       { skillC: 3.96, skillN: 3.50, quadrant: '国产替代攻坚', advice: '标配' }
   AI应用及平台:   { skillC: 3.84, skillN: 3.67, quadrant: '攻坚/领跑边界', advice: '超配(择机)' }
   航天星链:       { skillC: 3.75, skillN: 3.50, quadrant: '换道领跑', advice: '标配' }
   创新药:         { skillC: 3.73, skillN: 4.00, quadrant: '换道领跑', advice: '超配' }
   ```
2. **SKILL-N 额外加分映射**：极度超配 +0.30 / 超配 +0.15 / 标配 +0.00

### Phase 2 — L-1 综合分计算与关联度校准

**目标**：按 L-1 评分公式合成综合分，并根据关联度系数校准，避免非核心标的拿到行业满分。

**交付物**：
1. **L-1 评分公式**（严格执行）：
   ```
   L-1 得分 = SKILL-C 总分 × 关联度系数 + SKILL-N 额外加分

   例：腾讯控股（AI应用及平台，核心标的关联度 1.0，超配）
       = 3.84 × 1.0 + 0.15 = 3.99
   例：某边缘光模块股（CoWoS，关键词匹配，关联度 0.6，极度超配）
       = 4.90 × 0.6 + 0.30 = 3.24
   ```
2. **边界守卫**：
   - Step 3 无行业报告：L-1 = null，V6 权重从 110% 重分配到其余层
   - L-1 得分夹取：[1.0, 5.0]，防止极端系数溢出

### Phase 3 — 注入 V6 模型与跨层校验

**目标**：将 L-1 结果注入 `v6-stock-analysis-model` 的 L-1 层，并与 L0（宏观）做跨层一致性校验。

**交付物**：
1. **V6 综合权重（含 L-1）**（110% → 100% 等比缩放）：
   ```
   L-1: 10% / L0: 10% / L1: 15% / L2: 10% / L3财务: 10% / L3估值: 10% /
   L4: 10% / L5: 5% / L6: 7% / L7: 15% / L8: 8%   → 合计 110% → 等比缩放至 100%
   ```
2. **跨层联动校验**：L-1 行业「政策契合」与 L0 宏观 STEEP「P-政策」评分偏差 ≤1 分；否则标注「L-1/L0 跨层偏差，建议复核」。

## 四、陷阱与经验教训（**至少 6 条，基于实战提炼，禁止空话**）

| # | 陷阱 | 后果 | 规避 |
|---|------|-----|-----|
| 1 | 非核心标的拿行业满分（关联度=1.0 滥用） | L-1 层虚高，误导综合评分 | Step 2 关键词匹配强制关联度 ≤0.9；只有 Step 1「行业报告明确列出的核心标的」才能 1.0 |
| 2 | 映射表硬编码新标的但 SKILL 评分未更新 | 新标的注入过时行业评分 | 每季度同步一次「核心标的列表 → 行业报告版本日期」，评分报告更新时同步刷新缓存 |
| 3 | 无行业报告仍给默认 L-1 分 | L-1 层注入假数据，影响 V6 综合评分 | **严格 null 策略**：Step 3 无覆盖 → L-1 = null，权重等比重分配到 L0/L1/L2 等其余层 |
| 4 | SKILL-N 额外加分与配置建议不匹配 | 加分错位（标配拿超配加分） | §一 Phase 1 加分映射与速查表 advice 字段强绑定，禁止手动改分 |
| 5 | 个股业务多赛道只取单一行业 | 漏掉第二/第三赛道评分，L-1 偏离实际 | 若个股跨 2+ 行业（如腾讯=AI+游戏+社交），分别取对应行业评分按营收占比加权平均 |
| 6 | 行业代码 slug 大小写不规范 | `v6-stock-analysis-model` 字典检索失败 | 维护统一的行业 slug 字典：CoWoS先进封装 / 芯片设计 / 机器人 / 量子计算 / AI应用及平台 / 航天星链 / 创新药，禁止变体写法 |
| 7 | L-1 与 L0 政策分严重不一致但未标注 | 报告自相矛盾，置信度降级 | Phase 3 跨层校验：|L-1政策契合 - L0-P政策| > 1 → 自动加注「L-1/L0 政策维度偏差，建议人工复核」 |
| 8 | Step 1「核心标的 1.0」关联度无报告原文支撑（仅泛泛描述「龙一/龙头」未附出处） | 关联度 1.0 被滥用；后续复核无法验证其核心标的真实性 | Step 1 命中核心标的时，evidence 数组必须引用行业报告原文片段（如「行业报告 P6 核心标的清单第一条」/「原文：×××为本行业绝对龙一，市占率 48%」），否则强制降为 Step 2 关键词匹配（关联度 ≤ 0.9） |
